# 山海经 · 放置挂机 —— 著录

一款以《山海经》为题材的纯前端放置挂机网页游戏（原生 JS，零依赖、无需构建、可离线运行）。

> 当前版本 **v1.15.8**（代号「五臧 · 续火」）· 更新于 2026-10-25。版本号与更新日期集中于 `GAME_META`（`src/gameData.js`），「叙录」页直接读取，不散落硬编码。

玩家扮演**著录者**，受命巡行南山，采集、制作、讨伐、御使、祭祀，把山川万物逐条录于竹简——游戏进度即一部正在写成的《山海经》。

- **技术形态**：纯静态站点（无后端），可直接部署 GitHub Pages；`localStorage` 存档，支持导出 / 导入；可选接入自托管云端存档（`server/cloud-save-server.js`，零依赖）实现多设备进度合并。
- **玩法骨架**：采用放置类游戏的通用设计模式（技能训练—挂机推进—离线结算、采集—加工—消耗三级闭环）；这部分属于不受著作权保护的通用设计。
- **内容来源**：世界观、山名、异兽、祠礼、征兆全部取自《山海经》原文（中华书局点校本《山海经校注》袁珂，公有领域）；所有数值、机制、命名均为本项目**自研调参**，未沿用任何既有产品。

## 界面（「朱墨套印本」）

视觉按一部双色套印古籍来做：**墨为骨、朱为记、青为纲**。全站只用三个功能色，且各有唯一职责——

| 色 | 变量 | 只用于 |
|---|---|---|
| 朱 `#B03A2B` | `--zhu` | 「此刻」与「动作」：当前页签、主按钮、进度、当前阶 |
| 石青 `#2E5269` | `--qing` | 「结构」：篇名、章节、链接、选中态 |
| 苔绿 `#566E4C` | `--tai` | 「所得」：增益、达成、已录 |

- **昼夜双态**：同一套「朱墨套印」色系延伸出两态——昼为纸底墨字，夜为暖炭底墨白字，夜间三色（朱/青/苔）微提亮以承夜光；顶栏「书脊」昼夜皆取最深一档，书脊不随室光而变。切换入口收在侧边栏末尾的「设置」页（昼夜一栏）（白昼 / 黑夜两态按钮），选择记入 `localStorage`，首次访问时跟随系统 `prefers-color-scheme`，切换过程带 0.3s 柔和过渡并在 `prefers-reduced-motion` 下降级为瞬切。
- **字体双声部**：标题用楷（`--f-kai`）作「书的声音」，正文用系统黑体（`--f-sans`）作「器物的声音」，数字统一等宽宋（`--f-num`）以免跳数。全部为系统字体栈，零外部依赖、离线可用。
- **平铺不叠影**：承载面一律 `1px` 细线 + 近直角（`2px`），不用圆角卡片与投影堆叠；层次靠留白与线建立。
- **原文竖排**：宽屏下山志「原文」以 `writing-mode:vertical-rl` 竖排呈现（窄屏回落横排）。这是全站唯一「用力」的地方，其余保持安静。
- **信息密度**：宽屏舆地为三栏「书案」布局（山系 / 诸山 / 山志各自滚动，整屏不空）；未解锁山系、一次未著录的异兽、未达标的异兽名单均折叠，避免开屏即长名单；图鉴 1112 条提供名/注音检索。
- **无障碍基线**：`:focus-visible` 焦点环、`prefers-reduced-motion` 降级、触控目标 ≥ 38px、文字对比度 ≥ 4.5:1（三级文字仍可读）。浮动通知层（toast）`pointer-events:none` 且落于顶栏之下，不遮挡、不吞点击。
- **交互反馈**：顶栏数值用等宽数字、变动时一次极短「落笔」高光；长页滚过一屏浮现「回到顶部」；图鉴检索命中以朱色淡底标出；空态（如御使无达标异兽）直接给出下一步行动按钮，不留死胡同。
- 样式全部集中在 `style.css`；`test/engine.test.js` 中有一组设计审计断言（色板、断点、抽屉宽度、网格密度、CSS 变量是否全部有定义等），改样式时同步维护。


## 运行方式

- **本地预览**：根目录起任意静态服务器，如 `npx serve` 或 `python -m http.server 8080`；直接双击 `index.html` 亦可游玩（个别浏览器下 `localStorage` 可能受限）。
- **部署**：推送到 GitHub 仓库 `main` 分支根目录，`Settings → Pages` 选 `main` / `(root)` 即可（已带 `.nojekyll`）。
- **存档**：进度存于本机浏览器（`localStorage`，每 5 秒自动写入），可在「统计」页导出 / 导入 / 重置。多设备同步将由**账号系统**统一提供，设置页不再要求手填服务器地址与令牌；底层同步层（可插拔后端 / 修订号乐观并发 / 多端合并）保留在 `src/save.js`，接入登录即可启用（见「账号与网游化」）。

## 世界结构

《山海经》的地理层级本身就是进度系统：**山系 → 区域，山 → 资源节点**。当前实现**南山经三系 39 山 + 西山经四系 77 山 + 北山经三系 88 山 + 东山经四系 46 山 + 中山经十二系 197 山（共 447 山、26 山系、五章，五臧山经全录）**（数据源 `nanshanjing_nodes.json` / `xishanjing_nodes.json` / `beishanjing_nodes.json` / `dongshanjing_nodes.json` / `zhongshanjing_nodes.json`，派生为 `src/nanshanData.js` / `src/xishanData.js` / `src/beishanData.js` / `src/dongshanData.js` / `src/zhongshanData.js`；改 JSON 后运行 `node scripts/gen-world-data.js` 重新生成）。

- **章节**：第一章·南山经（巡行记录）→ 第二章·西山经（神话舞台，神祇密度支撑主线章节）→ 第三章·北山经（长篇养成，精卫填海）→ 第四章·东山经（异兽谱系收束）→ 第五章·中山经（帝之密都，全书收卷；中次一至十二经 197 山全录，末山荣余落于 81 级，正合「九九八十一」之数）。
- **等级重排**：技能上限 81（九九八十一）。五章全球调参等级统一重排进 1–81：南山 raw[1,75] → [1,26]、西山 raw[78,275] → [27,42]、北山 raw[280,529] → [43,56]、东山 raw[535,690] → [57,68]、中山前三系 raw[691,749] → [69,73]（已上线，斜率固定）、后九系 raw[753,950] → [74,81]（两段式，补录不回头改旧章；后八系 raw 顺序紧排——中次十一经 48 山为全书最长系，均匀布局会溢出上限；已录：中次四经 753–775、五经 777–791、六经 793–806、七经 807–825、八经 826–848、九经 849–864、十经 865–873、十一经 874–921、十二经 922–950），原始调参值保留在各节点 `dataUnlockLevel` 字段，便于日后重新调参。
- 区域 / 节点按「舆地」等级解锁；三处「不可以上」之山另需「履险」等级。
- **舆地经验耦合**：一切修行（采集/制作/讨伐/祀/观）所得的 10% 同时长「舆地」、其半长「履险」——否则仅靠首访给经验，447 山的世界在真实游玩中永远走不通。
- 每座山的产出（其木多 X / 其阳多玉 / 有兽焉）直接来自原文，节点面板可查阅原文节录与神话段落。
- 征兆（原文「见则 X」）共 **45 条**（南山 8 + 西山 15 + 北山 4 + 东山 15 + 中山 3）：首次著录该异兽即触发全局吉凶事件，可卜筮预知、以祠祀禳解；**兵灾类可被御使駮「可以御兵」所御，鵕鸟/大鹗之诛赐予对应免疫；大风类（北山·山𤟤）影响移动效率、有恐类（北山·酸与）令卜筮失准；中山鸣蛇之大旱与化蛇/夫诸之大水为全书收卷的双重水旱兆**。
- 观象 / 观瑞 9 处（南山 5 + 东山 4），**谒见神祇 20 处 / 24 位**（西山 10 处 + 中山 10 处），养成点 **3 处**（峚山「玉膏灌丹木」五岁、咸山「器酸三岁」、发鸠山「精卫填海」——后两者为北山原文自带的长周期）。
- 特殊节点：积石之山（全产出）、鸟鼠同穴（共生采集）、昆仑（田地威胁）；北山新增白沙山（沙漠，与橐驼「善行流沙」配套）、洹山三桑（高百仞，需高阶樵采）、教山（冬干夏流季节河）、空桑（冬夏有雪）。**北次一经全域「生食不火」——燔燎/调鼎在该区禁用**。

## 核心系统

- **著录度**（替代通用熟练度）：每个可采集物 / 异兽 / 山川 / 神祇独立累积，五阶「初见 → 识名 → 明性 → 通形 → 得御」，阈值 1/10/25/50/100 次，阶位产出加成 +0/+8/+18/+32/+50%；每阶揭示一段原文，达标后解锁御使资格。
- **御使**（替代召唤）：异兽需著录至「通形」方可入槽，槽位随御使等级扩充（每 10 级 +1，至 9 槽）。异兽提供的是被动增益与自动作业（如狌狌「食之善走」提采集速度、鹿蜀「佩之宜子孙」助田事），符合「驯养使役」而非「召唤仆从」。**蛮蛮「一翼一目，相得乃飞」——成对御使，占两槽**。
- **征兆系统**：原文「见则 X」共 45 条，首次著录即触发；凶兆不是纯惩罚——可禳解、可卜筮预知、吉凶可对冲。灌灌「佩之不惑」使凶兆减半、卜筮必吉；駮「可以御兵」御兵灾；鵕鸟/大鹗之诛赐予对应免疫。北山新增大风（拖慢移动）、有恐（卜筮失准）两类全新 debuff；东山新增螽蝗为败（采集/制作下降）、多狡客（商旅/战利下降）、多疫/大疫（产出/离线下降）四类 debuff；中山经收卷双兆——鸣蛇大旱与化蛇/夫诸大水（水旱对冲）。
- **祠礼**：**二十八套（含常祭）**（南山三系 + 西山四系 + 北山三系 + 东山四系 + 中山十二系，祭法各异：太牢 / 少牢 / 雄鸡 / 羭山百牲斋百日 / 吉玉稷米 / 白鸡祈 / 白狗祈 / 璋玉瘗 / 北山瘗 / 北山投 / 北山玉璧瘗 / 东山犬鱼 / 东山鸡璧 / 东山羊黍 / 东山大牢 / 中山太牢吉玉 / 中山雄鸡糈瘞 / 中山一物祈珪 / 中山白鸡彩衣 / 中山肥牲吉玉 / 中山雄鸡禳祭 / 中山羊羞藻玉 / 中山雄鸡藻圭 / 中山雄鸡吉玉 / 中山雄鸡五种 / 中山雄鸡珪糈 / 中山雄鸡牝豚），「瘗」与「祈」仪式不同；行祭给该山系产出增益并收录山神。祠祀可排入巡历队列。
- **谒见**：西山与中山的二十处神祇**不可讨伐**——前往其山行谒见之礼，入图鉴并得祭祀经验；首次谒见另得「神赐」一件（如刚山神「神𩲜之足」——神祇不讨伐，唯谒见可得）。中山十位（武罗／泰逢／骄虫／𬠷围／计蒙／涉𬠷／神人／耕父／于儿／帝之二女）各有形态与司职在浮层。（陆吾/西王母/帝江为守关 BOSS，走讨伐）。
- **养成**：峚山「玉膏灌丹木，五岁乃成」——原文自带的长周期，五岁满得丹木与其果实。
- **五行战斗**（替代战斗三角）：相克 ×1.35 / 被克 ×0.75 / 同属 ×1.00 / 相生增益 ×1.15。战斗以「讨伐派遣」自动结算为主；异兽五行自研设定。
- **BOSS 序列**：六凶（凿齿三连啮 / 九婴五行嬗变 / 大风飘风闪避 / 猰貐革甲破甲 / 修蛇蛇毒 / 封豨半血狂暴）+ 刑天（无首重击）+ **西山三神（陆吾九部连击 / 西王母善啸震慑 / 帝江混沌嬗变）**——机制各异，非数值换皮。
- **句式模板**：全部消耗品文案统一用原文句式——「食之 X」（食之不饥 / 善走 / 无肿疾）、「佩之 X」（佩之不迷 / 不畏 / 不惑）、「可以 X」（可以为底 / 已痔 / 释劳）。

## 数值（自研，全部集中在 `TUNING` 常量表）

- 等级：每技能 **81 级 9 阶**（一九…九九），不用常见 99/100/120 上限。
- 经验曲线：`XP(L→L+1) = round(20·L^2.15 + 10·1.048^L)`，可配置、可调。
- 掉落：权重公式 `base × (1+0.02·(等级−需求)) × (1+0.3·著录阶/4)`，clamp [0.1, 5]。
- 离线结算：`offlineGain = onlineRate × eff × min(时长, 上限)`；eff = 0.55 + 0.05×相关技能加成（cap 0.85），上限 12h（仓廪 +2h、每处观象 +1h）。
- 以上均为调参起点，改 `src/gameData.js` 顶部的 `TUNING` 即可批量调整。

## 界面

竹简 / 绢帛 / 水墨 / 白描 / 矿物颜料视觉；色板取自传统矿物颜料（石青 #2E5C8A、石绿 #4A7C59、朱砂 #C3272B、赭石 #8C5A3C、藤黄 #D9A521、蛤白 #F4F1E8、墨 #2B2B2B）。数据呈竖排简册式分栏，进度以墨迹渐染表现，批注用朱砂小字。生僻字（𪁺𪁸、䍺、猼訑等）显示拼音注音，不留豆腐块。字体仅用系统衬线栈（思源宋体系），未部署任何商业字库 Web Font。

- **新手指引**：首次进入（无著录记录）自动播放六步引导，依次掠过舆地 / 技能 / 征伐 / 行装 / 行动 / 统计，讲解核心循环；完成后写入本地标记不再打扰，可在「设置」页「指引 → 新手指引」随时重看。
- **离线归来**：离山满 2 分钟后结算，弹出「离线归来」汇总（时长、效率、所得经验 / 著录 / 圃艺 / 物品）；短时离线仅以浮条提示，不打断。
- **常驻指引条**：舆地页顶部按当前进度给出下一步建议；其余页签顶栏同样常驻一条「下一步建议」（初学者的起点、可御使而未御使的异兽、刚解锁的山系、临阶突破的著录，或挂机编排提示），不靠弹窗也能持续引导；条末「前往 ›」可一键跳到相关页签；条末「✕」可关闭，设置中可重开。
- **移动端山系折叠**：窄屏（≤720px）舆地页默认收起尚未解锁的山系章节（保留「🔒 未解锁山系 N 章」开关，点按展开/收起），避免超长列表把地图与节点详情挤出首屏；PC 端山系列表始终全量常驻。

  - **行动链「下一步」**：技能／征伐／祠祀／行装／营造页尾给 1–2 个当下确实可做、且能一键完成的事（「一键种满 3 块空田」「材料已齐 · 制 X」「宜讨 Y」「清整售出 N 件」「营造 Z」），把采集→制作→祠祀→征伐串起来。

## 征伐页：316 只异兽怎么摆

全部异兽平铺是个不小的负担：316 张卡一次性生成，`#content` 的 DOM 有 85 万字符，切页、滚动、手机上的一次重绘都能感觉到顿。

现在按山系分组，默认只展开**当前所在山系**与**宜讨所在组**，其余折成一行「北次二经 · 异兽 · 12 种」，点开才生成卡（`data-loaded` 记状态，只生成一次）。首屏 DOM 降到 8.6 万字符，约原来的十分之一；折叠组内的卡不在 DOM 里，`patchBeastCard`（战斗结束只更新刚打的那只）因此要能容忍「找不到卡」——它本来就有这层保护。

特殊目标组（祷过之山可猎、六凶、刑天、西山神祇）数量少且不属于任何山系，一律常开，免得玩家以为「六凶」没了。

## 战斗的两条纵深

**其一，词条（养成分岔）**：同一件金剑，淬炼到 +9 是「更硬的基础值」，词条则是「乘区与手感的取舍」。十类词条按槽位分配——兵器只出锋/锐/烈/准/疾/饮/引，甲胄只出固/韧/棘/疾/饮，玉符只出烈/韧/棘/引。重铸一次换一组，代价是炭与贝币。

**其二，势与绝技（战斗节奏）**：命中积势、受击折势、连击加速积势；满 100 时下一击自动转为绝技，按流派取式——近战「断岳」×2.8、射术「穿云」×2.4（不耗矢）、祝术「五行合」×2.2（吃相生加成）。连击断在「自己没打中」上而非「挨了一下」，否则怪物攻速略快于玩家时这套机制等于不存在；势满时不再被受击打退，保证蓄满即能放出。**连战之间继承 60% 残势**——一场三五回合就结束的小怪战若每场从零起蓄，绝技在挂机里永远放不出来；败北则清零。竞技场为此多了一条势条、连击计数与绝技次数。

**其三，战法（姿态）**：流派决定「用什么打」，战法决定「怎么打」。四种姿态各改四项乘区：无（1.00/1.00/1.00）、疾攻（伤害 ×0.90、攻势 ×1.15）、沉稳（伤害 ×0.95、防御 ×1.25、减伤 ×0.90、攻势 ×0.90）、破军（伤害 ×1.18、防御 ×0.75）。与五行克制、词条、绝技互不覆盖，乘在一起才是一场的实际输出。

### 六凶的招式，得让人看见

六只 BOSS 各自带一条 `special`（猰貐「革甲」常驻减伤、封豨「狂暴」半血攻速翻倍、大鹗「阴阳嬗变」周期换五行……），实现都在战斗里跑着，界面却一个字没提——玩家只会觉得「这只怪怎么突然打不动了」。

现在两处可见：征伐弹窗单列一行「特性 · 常驻厚甲减伤，受击叠层破甲」，竞技场里敌人名字旁挂一枚朱色小印，悬停看全句。数据里那句 `' Periodic 大幅闪避'` 也顺手改成了中文。

## 收集线的闭环

图鉴 1122 条之上加了一层**「仅未录」筛选**：收集到后期，满屏都是已录的实心卡，想在里头找剩下那几条实在费眼。筛选行多一个「仅未录 N」，与名/注音检索叠加使用；尽收时给的是「本类已尽收」而不是「无此条目」。

**收集成就**（24 项）：十类各有「过半 / 尽收」两项，另设总录四档（25% / 50% / 75% / 100%）。与既有 Milestones 的分工是——前者**达成即生效**（被动加成），后者**达成待领**（去图鉴页领一次，贝币与材料才落袋）。领取记在 `stats.claimed`，随存档走；未领的会在图鉴页顶部条上标出数量。

## 采集可行性（等级阶梯与越级）

采集物的等级原本直接取自所在山的门槛（`autoLvl ≈ 门槛 × 0.86`），于是出现了几处断崖：**渔从 1 级到 30 级之间只有一种鱼可捞**（南山只有育沛），药 1→23、圃艺 5→29 亦然。玩家在这些技能上不是「练得慢」，而是「没得练」——只能反复刷同一种，实测渔 1→30 需两万四千次采集。

两处修正：

- **等级阶梯**：同技能的物品按等级排序后，相邻不得相差 8 级以上（只降不升）。`value` / `xp` 保持原值——那是内容价值，不该因为「更早能采到」而贬值。修正后渔的曲线是 1 → 8 → 16 → 24 → 32 → 37 → … → 68，每几级就有新鱼。
- **越级采集**：技能差 8 级以内仍可动手，效率按差距折减（`1 − 0.08 × 差`，最低 35%），产量与经验同步打折，山志里以虚线按钮标注「越级 84%」。差超过 8 级才真正锁住。

这条规则与「产地限制」互补：产地保证你得走到那座山，阶梯与越级保证走到了就采得动。

## 物品的「用途」

671 件物品里有 514 件不参与任何配方——采集到手，点开详情只看得到出处，不知道留着还是卖掉。现在详情多一栏**用途**：哪些配方拿它当料（燔燎·炭、锻冶·石斧、制箭·石镞…）、是不是祠礼祭品（朱色标出，如「祠礼·北次一·瘗礼」）、能否作种，若一无所用则直说「暂无合用之方」并给出回收价（「回收 9 贝 / 件」）。

判定完全由配方表反查得出，不另存数据——新增一条配方，相关材料的用途栏会自动多出一枚芯片。

## 物品的「来路」

`itemUses` 回答「这东西能干嘛」，反过来那一问同样要紧：差一头牛、缺一百枚玉的时候，玩家站在原地不知道往哪儿走。于是有 `itemSources`——按采集产地、配方、异兽掉落、墟市、嘉种、观瑞、谒见、养成八条线反查，全 671 件物品都能说出出处。

行祭时材料不备，不再只用一句 toast 打发，而是开一张清单：缺几件、现有几件，下面挂一枚枚「讨伐·㸲牛、豪彘、牦牛 等 6 种」「琢玉·需 66 级 · 美玉×2」的来路芯片。

反查过程顺手照出三处盲点：

- **作物没有来路**。稻米、稌米、白菅既是采集不到也不进配方，详情里只剩「回收 4 贝」——它们是种出来的，但没人去反查种子。现在按 `crop` 反查报「植 菅苗（18 秒熟）」。
- **BOSS 掉落被漏读**。小妖走 `loot` 表，BOSS 走单值 `drop`，而 `m.loot` 常常是空数组（真值），于是一律走了 loot 分支。凤皇羽、鹓雏羽、神𩲜之足三件因此查不到来路。
- **观瑞所赐写死在代码里**。`doObserve` 里有一张 `{ danxue:'fenghuangyu', nanyu:'yuanchuyu' }` 的临时表——物品表里没有这层关系，来源自然查不出。已挪进 `OBSERVE_SITES.reward`，代码只读数据。

顺带做了一次死代码清理：`skillLevelTag`、`xpBar`、`countCN` 三个函数留在文件里但无人调用（前两个是被后来的「页面等级条」取代的旧实现）。测试里加了一条静态检查——顶层函数必须「有调用点」或「有导出」，两者皆无即报错，防止下一次重构又留下孤儿。

## 祠礼：从文案到产能

二十八套礼制自入录起就写着「行祭之后该山系产出 +30%」，但 `regionRiteBonus()` 只被定义、从未被调用——采集那头一分都没多给。也就是说，玩家花一百枚玉、一百樽酒、一百头牺牲行的「羭山百牲斋」，当时换到的只有一段祭祀经验。这一版把它接回采集加成（在线与离线两处都接），礼才真有着落。

同一处还埋了个更隐蔽的问题：**同一山系可以有多套礼**（西次一经既有「华山太牢」30%，又有「羭山百牲斋」50% 两小时），而加成只按 `regionId` 反查 `RITES` 的第一条——行了大祭，拿到的仍是小祭的数。现在行祭时另记一笔 `riteOf[regionId]`，指明此刻在供的是哪一套；旧档没有这个字段，退回原逻辑，不会报错。

**续祭**要解决的是另一个尴尬：礼只有一小时（大祭两小时）的时效，到期就断。挂机一晚回来，加成早没了，而重备一次祭品要翻箱倒柜凑材料。现在每个祠礼方块右上角多一枚「续」——点开即交由门人代祭，到期前 60 秒自动重备同样一份祭品，扣料与手点一致。

- **祭品不继不关开关**，只转入「待料」：开关还亮着（描金改为描边），补上材料下一 tick 自会续上。若直接关掉，玩家得重新想起去点一次，这比自动关掉更烦
- **离线也补**：离山期间本应续上的那几份，按同样祭品顺延补扣（只补不预付，不超过当下），补完再结算采集，加成才算得进去。归来弹窗会列出补了几次、耗了什么
- **看得见**：舆地页的山系标题下多一条「🕯 首经祠礼　产出 +30%　42:10」，方块上也有余时角标——百分比加成若只躺在数据里，等于没有

### 「产出 +30%」到底加了多少

把加成接回采集之后，还有一处名不副实：所有 yield 类加成（祠礼、里程碑、御使、凤皇之兆）都走同一个通道——`chance(GATHER_DOUBLE + bonus × 0.5)`，加的是「一次得两份」的概率，而不是直接把件数乘上去。基础期望是 1.25 件/次，祠礼 +0.30 加的是 0.15 的双份概率与 0.036 的三份概率，折算下来真实产量约 **+15%**。

面板上写「产出 +30%」、玩家实测只多半成，第一反应是「这游戏有 bug」。所以现在两处都说：`采获 +30%（约合产量 +15%）`。数字没改（改数值会连带推翻已经调好的经济节奏），改的是说法——`riteRealYield()` 按同一公式折算，祠坛 ×1.5 时自动报 +22%。

## 离线归来

原来只报一句「修得经验 +12.3K」。可玩家想知道的是：这一夜在做什么、够不够本、是不是白挂了。现在弹窗按项列：

- **所做**——采集 960 次 / 制作 120 次 / 观象 30 次，按当时的行动类型给次数
- **上限**——离山超过收益上限时，红字写明「离山 10 小时 15 分，其中 2 小时 15 分超出 12 小时上限，未计入」。此前是静默截断，看着像吞了收益
- **续祭**——补祭次数与耗去的祭品，材料是实扣的，得让人知道扣在哪
- 其后才是经验、新著录、圃艺收成、所得

## 「写了但没人读」

上一版发现祠礼加成从未生效，这一版顺着同一条线索又扫出六处：

- **征兆的 dmg / loot / fish / build 四条通道**。45 条征兆里，37 条带 `war:true`（有兵），配的是 `dmg:-0.15, loot:-0.10`；13 条大旱配 `fish:-0.4`；狸力与鵹鹕的「土功」配 `build:0.2`。这四组数值都定义了，`omenMod()` 却只被 'yield/gather/offline/trade/craft/move/divine' 七种键调用过——也就是说，玩家触发「见则有兵」时，战斗里一分都没变。
- **征兆浮层的标签表**。比数值更早出问题的是文案：`omenEffectText` 的 map 只认得七个键，最凶的「有兵」点开浮层是**空白**——只写「见则有兵」，不说兵在哪儿。现在把标签抽成 `OMEN_EFFECT_LABELS`，浮层与顶栏汇总共用一张表，卡片点开写「伤害 -15%；所获 -10%」。
- **长线成就的 offlineCap / jisi**。「三谷观象」写着「离线上限 +1h」，`offlineCapHours()` 里却没有这一行——成就页亮着「已达成」，上限没动。同样，「西山百神」的 `jisi:0.20`（祭祀经验 +20%）也没人读。

顺带修正两处达成口径：

- **西山百神**原本数的是 `records` 里 `deity_` 开头的键（那是祠礼对应的神祇，27 个），与「谒见」毫无关系。玩家谒见完全部西山神祇反而不亮。现在按 10 处谒见点的 14 位神祇实计。
- **教程与玩法说明**里「离线上限最高 15 小时」早已过时（基础 12 + 七处观象 + 仓廪 2 + 土窟 1 + 成就 1 = 22）。改为读 `offlineCapHours()`；教程正文因为写在数组字面量里会被**求值一次就钉死**，改成 `body: () => ...` 延迟到渲染时才算。

测试里加了两条通用断言防止复发：`OMENS` 的每个数值字段都必须有 `omenMod('<key>')` 出口；`Milestones` 的每个数值字段都必须在 `game.js` 里出现。上一版那条「顶层函数必须有调用点或导出」也还在。

## 三处「地气」

`SPECIAL_NODES` 里有三座山只写了原文、没有机制：白沙山「广员三百里，尽沙也」、洹山「三桑无枝，其高百仞」、教山「冬干而夏流，实惟干河」。注释里甚至写了「与虢山橐驼『善行流沙中』配套」，配套的那半句一直没写。

现在各给一条轻量规则，并写进山志：

| 山 | 地气 | 影响 |
|---|---|---|
| 白沙山 | 流沙 | 采集间隔 ×1.25；御使**橐驼**后恢复如常（它「知水泉所在」） |
| 洹山 | 百仞 | 采集间隔 ×1.18，但采获加成 +10%（登高而取，所得更丰） |
| 教山 | 干河 | 按「候」（六小时）旱雨轮转：旱季渔获 −30%，雨季 +30% |

季节只有一处用到，所以没做成独立系统，只给了一个 `seasonPhase()`（`gameTime / 6h % 2`）——将来若要牵动更多物产，从这里长出去即可。

## 符箓要先「识得」

七张护符的数据里都写着 `reqRecord: { id, tier }`——迷榖符须著录迷榖至通形、文鳐符须著录文鳐至通形。这个字段从入录起就**没有任何地方读过**：打到符就能戴，符上那句「佩之不迷」跟它护的是什么东西没有半点关系。

现在补上了校验，并且三处都要管：

- `equipItem` 拒绝并说明「需著录「迷榖」至通形（今 识名）」
- `maybeAutoEquip` / `equipBest` 跳过未达标的（否则「一键最优装」会把戴不上的符塞进来，然后静默失败）
- 物品详情多一行「佩用」，未达标时朱色标出，装备按钮写「装备（著录未及）」

旧档里已经戴着、但前置不满足的符不会被强行脱下——那是个既成状态，强行收走只会让玩家莫名其妙；只是自动换装不再选它。

反查这一条时还发现 `reqRecordText` 把对象名读错了：`Items[r.id]` 里没有「迷榖」，因为那是异兽 id，落在 `Monsters` 表里。现在两张表都查。

## 数据与运行时

源数据（`*jing_nodes.json`）是工作底本，里面混着校勘记录与给我自己看的批注（`_meta.版本差异说明`、`★本轮新增…`、`可设计为…`）。这些**不进运行时**：`scripts/gen-world-data.js` 在派生 `src/*Data.js` 时剔除 `_meta` 并清洗叙述性字段中的编辑备注。

早先没有这一步，山志的「注解」栏里会直接显示「★可设计为特殊事件点」这类开发笔记——共 26 处「可设计为」与上百处 ★ 批注。现在源文件保留完整记录，页面只呈现原文与释义；测试里加了三条断言守着这条边界（不得含 `_meta`、不得含「可设计为」、不得含 ★ 开头的批注）。

## 账号与网游化（规划）

当前是纯静态单机：进度只在本机 `localStorage`。为将来接入账号登录与联网，数据层已按下面的方式预留，**不需要重写存档**：

**1）存档结构**（`src/save.js` · `serializeSave`）
- 负载是纯 JSON：`version`（存档版本，迁移用）、`savedAt`（毫秒时间戳）、`rev`（修订号，服务端乐观并发）、`deviceId`（设备标识）、以及游戏数据本体。
- 游戏数据按模块平铺（`skills` / `records` / `map` / `inventory` / `gear` / `enhance` / `farms` / `queue` …），便于拆分「增量同步」与「按模块合并」，服务端化时字段语义不变。
- 合并规则集中在客户端（`mergeSaves`）：经验 / 著录 / 统计取大，地图 / 背包并集，贝币取较新。服务端权威化时把同一套规则搬到服务端即可，客户端改为「上传增量 + 拉取快照」。

**2）登录接入点**
- `SaveManager.setCloud({ endpoint, token })` 是唯一入口：登录成功后由账号层调用即接管同步；退出登录调用 `clearCloud()` 回到纯本地。
- 同步状态（`syncReady()` / `syncState`）、防抖（`scheduleSync`）、离页强传（`flushSync`）、409 冲突重取都已实现，可直接复用。
- 设置页不再暴露「云地址 / 令牌」——它们属于账号系统，不该由玩家手填。

**3）服务端最小契约**（`server/cloud-save-server.js` 已按其实现）
- `GET /save` → `{ payload, rev, savedAt }`；`PUT /save` 收 `{ payload, rev, deviceId }`，`rev` 落后返回 409；`DELETE /save` 抹档。
- 接入登录后，在 `PUT` 前校验会话并落 `account_id`，即可从「单档」扩为「按账号存档」。

**4）待联网阶段再做**
- 账号表 / 会话 / 设备管理；服务端权威数值（防改档）；离线收益服务端结算；多人要素（排行 / 交易 / 协作）。
