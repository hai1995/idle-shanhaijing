## 本轮一句话

上线当天第一句反馈是「没有看见动画效果」。查下来动画确实在跑——
问题是**动得太稀**，而不是没跑。另加一处冗余清理。

## 先确认：动画到底有没有跑

采样 `.sc-tool` 的变换矩阵，六次采样六个不同值（+21° → −112° → 回位）：

```
0 {'matrix': 0.93022, -0.367003 ...}   +21°
1 {'matrix': 0.463999, -0.885836 ...}  +62°
2 {'matrix': -0.134865, -0.990864 ...} -98°
3 {'matrix': -0.373294, -0.927713 ...} -112°
4 {'matrix': -0.316359, -0.94864 ...}  -108°
5 {'matrix': -0.248019, -0.968755 ...} -104°
```

`animation-name: scSwing`、`duration: 3.25s`、`play-state: running`、
`transform-box: view-box`、`prefers-reduced-motion: false`。
**动画是跑的。问题是它没被看见。**

## 为什么没被看见

| 原因 | 具体 |
|---|---|
| **动作太稀** | 一个采集周期只挥一锄（2.6–3.3 秒），其中不到一秒有明显动作，其余时间锄头插在土里 |
| **动的只有锄头** | 人高 52px，锄柄在屏幕上挥动幅度约 20px，在余光里太轻 |

**玩家判断「有没有动」用的是一两秒的窗口，不是一个完整周期。**
「动画存在」看关键帧就够了，「动画被看见」要看**单位时间内的变化次数**。

## 第二个问题：确实重复

用户问「底部那个动作条与动画会不会重复冗余」。数了一遍，两处重复：

| 重复项 | 处理 |
|---|---|
| 仪表带的 `actionProg` 细进度条 + 现场底部朱线 | 现场显示时**收起仪表带的**（`#statusbar.scene-on`）；现场关掉时它照旧出现 |
| 仪表带「（招摇之山）」+ 现场右上角落款「招摇之山」 | **删掉现场的落款** |

顺带修：进度条收走后「停止」会紧贴行动名、右边空一块——让行动名吃掉剩余宽度，把停止顶到最右。

## 两层兜底（为什么这么加）

**① 整个人俯仰用 `<div>` 包一层**
锄头的旋转是 `SVG <g>` 上的 CSS transform。现代内核没问题，
但部分内核对 SVG 内部元素的 CSS transform 支持不全——真遇上了人就定住。
`.sc-rig` 是个 div，div 上的 transform 所有内核都吃。
最坏情况是锄头不动、人还在晃，总比整块静住强。

**② 产出闪光用 `opacity`**
`opacity` 动画在所有内核对所有元素都稳，且「闪一下」在余光里就能察觉。
哪怕别的动效全废，出货这件事仍看得见。

## 一条新规律（写进 ROADMAP）

**「动画存在」和「动画被看见」是两件事。** 前者看关键帧，后者看单位时间内的变化次数。
同一句反馈里往往还藏着第二个问题——这次是「重复」。
**加了新画面之后，要回头数一遍屏幕上还剩几处在说同一件事。**
