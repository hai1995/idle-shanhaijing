## 本轮一句话

采集是玩家九成时间在做的动作，而它此前的全部视觉反馈只有一根细进度条。
这一版给仪表带下方加了 74–96px 的「现场」：山、人、锄、土、收成、记账。

## 诊断：盯屏幕时原来能看到什么

| 页面 | 原来盯着看有什么 |
|---|---|
| 征伐 | 血条、回合、伤害，每 250ms 刷新 —— 唯一「活着」的页面 |
| 采集 | 一根 `actionProg` 细进度条；采到什么，技能卡上飘一个「×1」，一秒后消失 |
| 舆地 | 静态方块列表 |

**所以「没内容可看」的根因不是缺一张地图，而是最常做的动作没有任何画面。**
前三轮（v1.31.51~53）做地图全部下线，绕的正是这个弯。

## 一条必须对齐的因果

锄头落下的时刻，必须就是引擎产出物品的时刻。

周期不用固定值，`--ai` 直接取 `currentActionInterval()`；帧序把「落下」排在 92%：

| 帧位 | 动作 |
|---|---|
| 0% | 锄在土里 |
| 46% | 举到竖直偏右 |
| 62% | 最高点略停（有「抡」的分量） |
| **92%** | **落下、插入土中 ← 引擎正好在这一刻产出** |
| 100% | 锄在土里 |

土粒的关键帧卡在同一段（88%–99%）。顺序对了，玩家看到的是「这一锄挖出来的」；
顺序反了，就变成「先出东西、人再动一下」，像在放幻灯片。

## 三处工程决定

**① 纯视觉层，零平衡风险**
`scene.js` 不调 `giveItem` / `gainXp` / `addRecord`，不碰 `Game.shells`。测试逐条钉住。

**② 挂在静态节点上，增量更新**
各页都是 `innerHTML` 整块重绘。现场若在重绘范围内，动画每渲染一次就归零。
故 `index.html` 给静态的 `#sceneBar`，只在「场景签名」变化时重建，数字变化时只改一个文本节点。

**③ 签名不含计数**
`sceneSig` 里没有「已采几件」，否则每采一次就重建一次，挥锄动画被打断在开头。

## 不给计数的地方就不给

观象、谒见、莳植没有「一件一件出东西」这回事。摆一个永远是 0 的大数字比不摆更让人困惑——
那几档只写名号（`.sc-label`）。

## 版式

| 场景 | 画布高 | 人 |
|---|---|---|
| 手机（≤560px） | 74px | 52×60 |
| 默认 | 82px | 52×60 |
| 宽屏（≥1000px） | 96px | 62×72 |

宽屏要单独抬高一档：82px 摊在 1080 宽的屏上像一条书签，人只有指甲盖大。
山形 `viewBox` 也用 700×64（比例 10.9）而非 400×64（比例 6.25）——后者宽屏要横拉 2.7 倍，
山形会被压成一条几乎笔直的波纹（原型里踩过）。

## 能关掉

设置 →「行动现场画面」（`Prefs.sceneOn`）。手机屏高宝贵，82px 是 82px。
关掉整块隐藏，仪表带照常。`fxLevel === 'off'` 时保留静帧：画面还在，只是不动。

## 四条规律（写进 ROADMAP）

1. **先量「玩家九成时间在做什么」，再决定加什么内容**——给最常待的地方加画面，
   比加一个新玩法收益高一个数量级，成本却只有十分之一。
2. **反馈的时序就是因果**——周期绑 `currentActionInterval()`，落点排在周期末尾。
3. **innerHTML 重绘与动画天然冲突**——必须挂静态节点 + 增量更新，签名不含计数。
4. **纯视觉层要能被证明「没动数值」**——测试断言它不含 `giveItem` / `gainXp` / `addRecord`。
