## v1.31.7 「夜间维护」 · 2026-10-26

> 一整夜的自治维护：性能 / 健壮性 / 工程化 / 数值测量，玩法数值一个没动。

**性能**
- 战斗 HUD 每 250ms 无条件重写 `innerHTML` / `textContent` / 样式，改为「值未变不写」；
  估值块用 `cls+html` 签名，避免持续重建节点。
- 顶栏增益按钮同值不写 `textContent` / `title` / `classList`；浮层刷新节流 1 秒。
- 技能页切换行动不再整页重建（26 技能卡 + 全部配方 + 田地），只切高亮；
  实测从 `scrollY=600` 开始制作，位置保持 600。
- 技能页经验条改为每秒跟进（此前只在切页时更新，挂机盯着看像没在涨）。
- `toast` 同句去重 + 同屏至多 4 条（挂机回来曾叠七八条盖住半屏）。

**BUG**
- **「材料存余」恒为 0/N**：`materialStatusForSkill` 读的是 `Game.inv`，库存字段其实叫
  `Game.inventory`。技能卡浮层与详情里每一行都标着缺料，备了 7 份怪木还写着 0/1。
- **缺技艺的旧档读进来技能页必崩**：`renderSkills` 直接读 `Game.skills[id].level`。
  读档时补全缺失技艺（1 级）、等级夹到上限、xp 非法则回填。
- **制作用动的配方是快照**：配方改过数值后旧档按过期材料继续做。读档时按 `type::out`
  重绑到当前表；配方已删则停掉该行动。

**工程化**
- 新增 `package.json`（零依赖，仅 scripts）与 `scripts/check.js`：
  版本一致 → 测试 → 审计 → 构建，一条命令 1.6 秒。
- 新增 `scripts/measure-ttk.js`、`scripts/measure-rebirth.js`、`scripts/fuzz.js`
  （均为只读工具）；`npm run check / ttk / rebirth / fuzz`。

**数据审计**新增四类：三签 key 必须在 `stats` 里、物产 `nodes[]` 每座山必须存在、
墟市在售之物必须存在且价量为正、配方溢价阀值 25 倍。

**测量结论**（详见 `docs/BALANCE.md`）
- TTK 分布：四段中位 10.2 / 15.3 / 16.5 / 17.1 秒，无一只越 32 秒——中期没有断层。
- 轮回曲线：单位时间修为 ∝ 乘区²；第 6→7 转因起手封顶出现 6% 凹陷（非 bug）。
- 配方溢价：最高 16.5 倍（琅玕剑），市廛不卖金属与炭，不构成刷钱循环。

**验证**：测试 1875 条全绿；数据审计零悬空；单文件版构建通过；
13 个页签 739 次 onclick 遍历零错误；5 个种子约 1.3 万次随机动作零异常。

## v1.31.6 · 2026-10-25

- **移动端行动页的条目挤成竖排**：一条队列里塞着「序号 / 名 / 进度 / 耗时 / 阻塞原因 / 三个按钮」，窄屏下名字被压成每行一两个字，页面也被撑出横向滚动。改为两行：第一行 序号 · 名 · 按钮，第二行 进度 · 耗时 · 原因（`.qi-meta` 统一承载）。
- **弹窗三段化**：标题固定、内容区自己滚、按钮固定在底部。原先整盒一起滚，物品详情 / 离线归来翻到一半按钮就滑出视野，手机上还得滚回去点。`#modalBox` 改 flex 列 + `max-height:min(86vh,780px)`，移动端用 `100dvh - 24px`；顺手关掉背景滚动（`body.no-scroll`），点遮罩也能关。
- **售卖 / 购入 / 制作都能填数量**：行囊物品详情与市廛都改成「− 数字 ＋ 全部」的交易区，底部按钮跟着数量走；制作弹窗可填「做几次」，另有「连作至料尽」。原先只有「1 / 全部」两个死档位，想卖 37 件里的 20 件得点二十次。
- **单击一律先出详情**：技能卡、配方卡、市廛商品与出售格，点一下都先开详情弹窗，再在弹窗里操作。手机没有 hover，原先技能卡的「产出地 / 材料来源 / 将至」、配方的「材料缺口」全在浮层里，触屏等于不存在。旧的 `UI.craftDenied`（只弹一个缺料 toast）随之撤掉。
- **顶栏报剩余场次**：限次往讨显示「往讨：鴸（余 3 场）」，无限连战不写「余 N 场」（那种打法没有「还剩」这回事）。收兵后顶栏自动回到实际状态。

## v1.31.5 · 2026-10-25

- **离线祠礼加成是线上的两倍**：`settleAway` 里写 `1 + regionRiteBonus(...)`，直接乘 1.30；而线上这笔加成落在「得两份 / 三份」的几率上，+30% 实际只有约 +15% 产量（`riteRealYield`）。同一件事又写成了两处口径——离线白拿一倍于线上的礼。改为 `1 + riteRealYield(...)/100`。
- **祠礼浮层显示「这一礼值不值」**：祭品按市价折贝币、本域一小时约采多少、此礼多得多少、多久回本，都在 `riteWorth()` 一处算（面板上的字与 `docs/BALANCE.md` 的表读同一份代码）。
- **建 `docs/BALANCE.md` 数值账本**：把三项「待验的账」一次量完——祠礼收益/成本（26 套小礼中位 1:314、最慢 82 秒回本，羭山大祭 56 分钟）、强化 +30（中位 225 次 / 4,746 炭 / 117 万贝，约 6 小时；并记下「去掉火候后 300 次模拟全部发散」）、三签赏钱（占同等级一小时收益的 0.03%，刻意不涨）。ROADMAP 相应划掉，并补一条「给祠礼加香火钱」的否决理由。
- **「讨伐 Lvundefined」**：缺料提示会拼出物品来路，讨伐来源没填 `lvl`，界面上就成了「羊牲：讨伐 Lvundefined · 羬羊」。补 `needLvl` 最小值，并让渲染对没有等级的来源（观瑞 / 谒见 / 神兵 / 养成）不再硬拼 Lv。

## v1.31.4 · 2026-10-25

- **离线结算三条与线上不一致的账**：
  1. 采集只认主产地（`it.node === Game.node`），而 309 件物产用 `nodes[]`——站在次产地下线一小时颗粒无收（如梓：主 nanshan-2-14 / 次 zhongshan-2-06）；在线却照采。改后同点离线所得 1453。
  2. 离线采集不认「越级 8 级内硬采」，比在线更严。改后差 6 级可得 755（打折），差 19 级仍为 0。
  3. 离线制作把每件写死 2.0 秒，灶窟（×0.9）与毕方「讹火」（−20%）在离线下等于不存在。改后取 `currentActionInterval()`：一小时 3600 → 有灶窟 4000 件。
