## v1.31.66 · 2026-10-26（夜间修补·三）

三件不改变玩法的事：

| 版本 | 处 | 做了什么 |
|---|---|---|
| 1.31.64 | 存档 | 补迁移链测试：v1 存档一路升到当前、幂等、未来版本原样保留、脏输入不抛。顺带给 `migrateSave` 加一条「存档比代码新」的提醒（主屏幕里的旧缓存会遇到） |
| 1.31.65 | 无障碍 | `#toasts` 加 `aria-live="polite"` + `role="status"`，读屏用户也能听到「材料不足」「已著录」 |
| 1.31.66 | 现场 | 四条 if 链收成 `SCENE_KINDS` 注册表；**顺带修 `stopSceneMotion()` 停不掉**——`cancelAnimationFrame` 拦不住正在执行的那一帧，而它末尾又排下一帧，于是关掉现场后仍在后台每帧跑 |

那条「停不掉」是用**像素比对**发现的：同一场景两次抓图总有几十个像素不一样。
查下去不是渲染不稳，是基准图本身在动——`stopSceneMotion()` 之后锄头还在挥。
修法是代次令牌：停一次 +1，在途的那一帧看到代次变了就自行退出。

> 教训：**验证重构时，"看起来一样"不算证据**。这次把 6 种行动 × 2 个主题的
> `sceneHtml` 输出逐字符比对，12/12 相同——比截图比对可靠得多，也正是它让
> 「那几十个像素」暴露成了一个真 BUG。

## v1.31.63 · 2026-10-26（夜间修补·续）

时长也统一了：界面 `fmtTime` 只写到「小时」，战绩 `fmtDur` 有「天」、整点还写成「1 小时 0 分」。
现在一份实现——取两个最大单位、整点不写零头，`90000 → 1 天 1 小时`。
`fmtClock` 不动：那是钟面读数（`H:MM`），不是话里的时长。

## v1.31.61 · 2026-10-31

**夜间模式 + 更多行动画面**

### 一、现场不跟着变暗，不是「少写了几条 night 规则」

截图里整页都转成了暖炭底，只有仪表带下面那条还是白纸。查下去是三处写死：

| 位置 | 写死的东西 |
|---|---|
| `.sc-wrap` | 底色 `#F5F2E8 → #EAE5D6` |
| `.sc-sky` | 天光 `rgba(255,255,255,.55)` |
| `SCENE_INK` | 五系墨色是深蓝、深绿、深赭——放在 `#17140F` 上对比度只有 1.6:1 |

前两处改成 token（`--paper-3/--paper`、`--sc-sky`），第三处加了一套夜间墨色：
同一色相提亮到 4.5:1 以上。**判据仍然是 `sceneInkOf` 一处**，只是多一个调色板。

还有一条容易漏：现场的颜色是渲染时写进内联样式的，不是 CSS 变量。
所以 `applyTheme` 里必须重画一次，否则切到夜间后那条现场留着一身「日间的深墨」——
整条看不见，比白色更糟。

### 二、征伐也进了现场

此前 `sceneState` 对战斗直接 `return null`：理由是「征伐页自有战斗画面」。
但那是**页面**上的血条与战报，玩家挂机打怪时如果停在别的页签，就什么也看不见。

现在战斗是第六种现场：

| 行动 | 物 | 动 |
|---|---|---|
| 采集 | 锄 + 土堆 | 举—落，土粒迸开（原有） |
| 制作 | 锤 + 砧 | 同一套举落，柄短一截 |
| 莳植 | 灌木 | 风里轻摆（CSS） |
| 观象 | 星 + 月 | 闪（CSS） |
| 谒见 | 三级台阶 | 静（「谨候阶下」字面就是阶） |
| 征伐 | 剑 + 兽 | 缩半步再前冲 9px，命中迸四点火星 |

两条设计约束：

**① 节拍取「几秒一击」，不是「几秒一采」。** 动画周期必须等于产出周期，
否则「一击一伤」的因果会错位——与采集那条是同一个道理，只是换了时间源
（`Game.combat.timer / playerAttackInterval()`）。

**② 工具只换尺寸，不换时间轴。** 动作的节奏属于「人」，不属于工具。
所以 `SCENE_KIT` 只给柄向量与刃宽，`SCENE_SWING` 那张帧表两种工具共用。

**规律**：一套动画要复用到第二个场景，先问「哪部分是节奏、哪部分是造型」。
分开之后，加一种工具只是加一行数据；混在一起，就得再写一套时间轴。

## v1.31.60 · 2026-10-31

**指引条被压成了三等价**

顺手在手机尺寸下量各页版面，发现这条常驻在除舆地以外每一页顶上的指引条，
正文只剩 101px：图标 101、正文 101、「前往」101。

```css
.hint-banner span{ flex:1; }      /* ← 三个 span 一视同仁，均分 */
```

于是每条指引都读成「先从『舆地』选山，点其中一项…」，后半句永远看不见——
一条天天在眼前、却永远说不完整话的提示，比没有更烦。

改成只让正文那一格伸缩，图标按内容宽（15px），「前往」按内容宽（28px），
正文从 101px 涨到 259px，两行能放下了。

**规律**：`flex:1` 要写在「该伸缩的那一格」上，不能写给「所有 span」。
选择器越短越像偷懒，代价是版面按元素个数均分。

## v1.31.59 · 2026-10-31

**「Safari 里直接开有动画，添加到桌面就没有」**

这条反馈比「丑」有用得多——它把问题从审美拉回了工程。

### 根因：自调度写在了 rAF 回调的开头

```js
const step = ()=>{
  UI._sceneRaf = requestAnimationFrame(step);   // ← 先排下一帧，再干活
  ...
};
```

iOS 把「添加到主屏幕」的网页放进独立 WebView，切后台/挂起时会把**已排队但未执行**
的回调直接丢掉。丢一次，链就断了。更糟的是 `UI._sceneRaf` 里还留着那个死掉的 id，
而重启的判据是：

```js
if (UI._sceneRaf) return;    // id 非 0 就当成「还在跑」
```

于是**永远不再启动**——一条死链把唯一的救活入口也锁死了。桌面浏览器里切标签页
通常不会丢回调，所以只在手机独立模式下复现。

### 四处一起改

| 改动 | 为什么 |
|---|---|
| 自调度挪到 `finally` 里、画完再排 | 一帧被丢，最多丢一帧，链自己接得上 |
| 切后台主动收链，回来重开 | 不让系统有机会「挂着一个待执行的回调」 |
| 用**心跳**（`_sceneLast` 时间戳）判断是否还在跑 | id 非 0 不等于活着；超过 1.2s 没出帧就重启 |
| watchdog 每秒看一眼，连试三次救不回来就降级 CSS | 环境压根不给 rAF 时也得动 |

### 降级层：转 div，不转 `<g>`

`#sceneBar.fx-css .sc-stage` 用 `scFallback` 关键帧绕握点转。转的是一个 **div**，
不是 SVG 图形元素——这是三次「手机不动」换来的教训里最硬的一条。
降级后相位只按墙钟走、与产出不同步，但「在动」比「准却不动」要紧。

### 诊断搬进设置

`?probe=1` 在独立模式下用不了（没有地址栏）。设置页新增「现场诊断」开关，
左下角一行显示 `帧 N · 相位 x · 间隔 ys · 迟 ms · 谁在驱动`：
帧数不涨 = JS 没跑；迟 = 停 = 链断了；`CSS（JS 停摆）` = 已降级。

## v1.31.58 · 2026-10-30

**「你这动画也太丑了」**

能看见动了，但造型不能看。回看三版，丑的原因不止一个：

| 版本 | 画法 | 丑在哪 |
|---|---|---|
| v1.31.54 | 细线条人（stroke 2-3） | 52×60 的框实际只显示 40 来像素，线条在这个尺寸下必然是**火柴人** |
| v1.31.55 | 加了「整个人俯仰」 | 俯仰幅度只有 3°，肉眼看不出，等于没改 |
| v1.31.57 | 实心剪影 | 袍身是个**直边梯形**，侧面看像一只「砖头」；头 r=4.9 偏大，像大头娃娃 |

这一版改四处：

**① 躯干用手绘弧线，不用直边**

真人的侧面有后脑的弧、肩背的外凸、臀的起伏。四边都带 `Q` 曲线的轮廓，
和「一块砖」的全部差别就在这几笔。

**② 头缩到 r=3.3**

真人头约占身高 1/7.5。上一版 1:5，偏卡通。

**③ 举起时让锄头「竖起来」**

这是最要紧的一处。柄的静止角是 69°（指向右下），只转到 −106° 时柄角还有 −37°——
**等于把锄头横着端在胸前，看着像举枪**。转到 −138°，柄角 −69°，锄头几乎竖直，
才像「抡起来要砸下去」。

**④ 前景坡抬高到 32px，挡住小腿**

人是站在坡后的，不是站在一条线上的。遮住脚踝以下，「接地」这件事就成立了。

**节奏也改了**：v1.31.55 一个周期塞两锄（3 秒挥两次，比真人快一倍，像抽搐）。
现在一锄一周期：抬 0.65s、停 0.26s、落 0.5s，其余时间静止（呼吸与飞鸟仍在动）。

**测试**：第 145 节跟着改了三处——握点坐标、一次落下、举起角度必须 < −120°
（这条断言就是「别再把锄头横着端」）。

**一句实话**：纯手写 SVG 在这个尺寸上能到的上限，大约就是「一眼认出是个人在锄地」。
要再往「好看」走，得引入真正的美术资源或改用工笔线描——那是另一个量级的工作。

## v1.31.57 · 2026-10-30

**第三次「手机不动」，这次先装真内核**

前两轮我都在桌面 Chromium 上验证，用户用的是 Safari。这次把 WebKit 装进沙箱，
在 Safari 的引擎上实测——结果推翻了我上一轮的判断：

| 在 WebKit 里测 | 结果 |
|---|---|
| `<g>` 上写 CSS `transform` | **生效**（包围盒从 40×40 变 56.6×56.6） |
| `<svg>` 根元素写 CSS `transform` | **生效** |
| div 写 CSS `transform` | 生效 |

**也就是说：Safari 的 SVG 的 CSS transform 是支持的。我上一轮的归因是错的。**

那真正的变量在其他地方。这一版同时处理三件：

**① 绕开 transform，直接算坐标**

不求「哪种 transform 写法 Safari 认」，改为每帧算锄头的两个端点、写 `path` 的 `d`：

```
握点 (30,38) 固定 → 柄末端 = 握点 + R(角度)·(11,28)
刃 = 末端 ± 垂直方向 × 5.4
```

`d` 是 SVG 1.1 的核心属性，没有内核会不支持。这一条不是「更兼容」，是**不需要兼容**。

**② 给所有资源加版本串（这条可能是真凶）**

GitHub Pages 给静态资源的 `Cache-Control` 是 `max-age=600`——**10 分钟**。
玩家在推送后立刻刷新，拿到的很可能还是旧文件。
于是前两版改的东西，用户手机上可能一次都没到过。

现在 `index.html` 里所有 `src="src/*.js"` 与 `style.css` 都带 `?v=1.31.57`，
每次发版改这个串。构建脚本与测试里的解析正则也一并适配。

**③ 加一个自查入口 `?probe=1`**

三次隔着屏幕猜哪一环断了，代价太高。现在打开 `index.html?probe=1`，
现场条左下角会显示一行小字：

```
帧 130 · 相位 0.70 · 间隔 3.25s
```

| 看到什么 | 说明 |
|---|---|
| 帧数不涨 | JS 没跑，或页面还是旧版（缓存） |
| 帧数在涨、相位不动 | 引擎没在推进 |
| 都正常却「看不见动」 | 才是渲染或视觉的问题 |

**测**：第 145 节改指新实现（`sceneToolPath`、写 `d`、握点恒定、探针入口）。
引擎测试 2671 通过 / 0 失败；WebKit 实测 `d` 属性六次采样六个值。

## v1.31.56 · 2026-10-30

**手机端：两版都没动**

v1.31.54 上线，用户说「没看见动画」；v1.31.55 加大幅度、加全身俯仰，用户说「手机上还是没动」。
两次我都在桌面 Chromium 里采样变换矩阵，数值确实在变——**这说明我的验收方式本身有问题**。

**换掉驱动方式，不再赌内核**

前两版依赖两条 CSS 路径：

1. `SVG <g>` 上的 CSS `transform` — 部分移动端内核对不齐；
2. `animation` 简写里带 `var(--ai)` — 简写属性里塞 CSS 变量，解析失败的引擎会直接丢弃整条声明。

与其逐条猜哪条没生效，不如换成最土的办法：

**一个 HTML 元素 + 一条内联 `transform`，每帧由 JS 写。**

具体改了三处：

| 项 | 之前 | 现在 |
|---|---|---|
| 锄头所在 | 人物 SVG 内部的 `<g class="sc-tool">` | **独立的 `<svg class="sc-tool">`**，绝对定位在握点 |
| 旋转来源 | CSS `@keyframes scSwing` | `UI.startSceneMotion()` 里的 `requestAnimationFrame` |
| 时长来源 | `animation-duration: var(--ai)` | 每帧直接算，不经过 CSS |

**顺带得到的好处：相位不再另建时间基准**

角度不是按「页面打开后过了几秒」算，而是按**引擎自己的进度**：

```
p = activityProgress / currentActionInterval()
```

于是暂停、变速、换物、离线补算回来之后，锄头永远落在正确的相位上——
「第二锄落下 = 产出物品」这条因果，从此不依赖任何定时器对齐。

**角度的两张帧表**

| 帧位 | 工具角度 | 身体角度 |
|---|---|---|
| 0% | +6° | 0° |
| 15% | −98° | −2.2° |
| 29% | +4° | +3.2° |
| 56% | −114° | −2.6° |
| **92%** | **+4°（产出）** | **+3.6°** |
| 100% | +6° | 0° |

分段插值里加了缓动——纯线性的挥动像机械臂。

**验证方式也换了**

不再只看「动画名对不对」，而是：**注入 `*{ animation: none !important }` 把整页 CSS 动画全部禁掉，再看锄头还动不动。**

结果：六次采样六个不同角度（−77° → −17° → +4° → +6° → −39° → −97°）。
**CSS 全禁之后仍在动**——因为驱动它的是 JS 和一条内联 transform。

**再加一层兜底：拿不到进度就按墙钟走**

相位本来取 `activityProgress / interval`。这是跨 script 读的顶层 `let`——
正常环境没问题，但万一某个环境读不到，相位会恒为 0，锄头就定在那儿。
所以加了一行：读不到就退化为 `performance.now() % 周期 / 周期`。
**宁可相位与产出的对齐略有偏差，也不能定住不动。**

**测**：第 145 节改指新实现，新增「工具不在人物 SVG 内部」「每帧写内联 transform」
「相位取 activityProgress / interval」「CSS 里不再有挥锄动画」等断言。
引擎测试 2665 通过 / 0 失败。

## v1.31.55 · 2026-10-30

**上线当天用户反馈：「没有看见动画效果」**

先查了是不是真的没跑。在 Chromium 里采样 `.sc-tool` 的变换矩阵，
数值一直在变（+21° → −112°）——**动画是跑的，但玩家看不见**。

原因有两个，都不是 bug：

1. **动作太稀**。一个采集周期只挥一锄，2.6–3.3 秒里只有不到一秒有明显动作，
   其余时间锄头插在土里不动。盯着看的人等两秒没动静，就判断「没有动画」。
2. **动的只有锄头**。人高 52px，锄柄在屏幕上挥动幅度约 20px，在余光里太轻。

**同一句反馈里还有第二个问题：「底部那个动作条与动画重复吗」**

重复。仪表带上有一根 `actionProg` 细进度条，现场底部又有一根朱线；
仪表带写「采玉：赤金（杻阳之山）」，现场右上角又落一次「杻阳之山」。

**改法**

| 项 | 之前 | 现在 |
|---|---|---|
| 挥锄频率 | 一个周期 1 锄 | **2 锄**（第一锄松土、第二锄出土） |
| 谁在动 | 只有锄头 | 锄头 + **整个人前后俯仰**（`.sc-rig`） |
| 远处的鸟 | 静止 | 19 秒缓慢飘移 |
| 产出反馈 | 只有物品浮起 | 加一层 **0.5 秒朱色淡光**（`.sc-flash`） |
| 仪表带进度条 | 与现场重复 | **现场显示时收起**（`#statusbar.scene-on`） |
| 现场山名落款 | 与仪表带括号重复 | **删除** |

**为什么加「整个人俯仰」这一层**

锄头的旋转是 `SVG <g>` 上的 CSS transform。这在现代内核里没问题，
但部分内核对 SVG 内部元素的 CSS transform 支持不全——真遇上了，人就定住不动。
所以把人包进一层 `<div class="sc-rig">` 做整体 rotate：**div 上的 transform 是所有内核都吃的**。
最坏情况是锄头不动、人还在晃，总比整块静住强。

**为什么加「产出闪光」这一层**

同理，这一层用 `opacity`。`opacity` 动画在所有内核对所有元素都稳，
且「闪一下」在余光里就能察觉。这是保底：哪怕别动效全废，出货这件事仍看得见。

**因果没有破**

两锄里，**第二锄落下仍排在周期 92%**——正是引擎产出物品的时刻。
第一锄是「松土」，落点在 29%，只带一小撮土，不出东西。

**测**：第 145 节补 6 条——一个周期两次落下、`scRig` 层存在、
`#statusbar.scene-on #actionProg` 收起、现场不复述山名。

## v1.31.54 · 2026-10-30

**采集是这个游戏最核心的动作，却是最没有画面的动作**

玩家九成时间在采。此前的全部视觉反馈是：仪表带上一根细进度条，
采到了在技能卡上飘一个「×1」，一秒后消失。

地块、人、动作——一概没有。所以「盯着屏幕时没内容可看」的真正原因，
不是缺一张地图，而是**最常做的事没有任何画面**。

**做了一块「现场」**

仪表带下方 82px（手机 74px）的一条画面，当前在做什么就画什么：

| 元素 | 内容 |
|---|---|
| 远处 | 三层水墨山形（首层主峰在人头顶，取「人在山脚」的意思） |
| 地面 | 一条起伏的土坡线，不是平直色带 |
| 人 | 躬身朝右的简笔劳作者，肩背有袍身块面 |
| 工具 | 采集用长柄锄、制作用锤；其他行动静立 |
| 落点 | 挖掘点 + 土粒，随挥锄迸开 |
| 收成 | 物品图标从土里蹦出、向右上飘走；**初见**另加朱框标记 |
| 记账 | 右侧大数字「这一回已采 N 件」+ 节奏「每 N 秒一采」 |
| 落款 | 右上角山名，仿古籍插图的墨书小字 |
| 进度 | 底部 3px 朱线，与仪表带那根同步 |

**一条必须对齐的因果**

锄头落下的时刻，必须就是引擎产出物品的时刻。

所以挥锄动画的周期不用固定值，而是 `animation-duration: var(--ai)`，
`--ai` 直接取 `currentActionInterval()`——采集间隔多长，挥一次就多久。
帧序也刻意把「落下」排在周期的 92%（而不是开头）：

```
0%   锄在土里
46%  举到竖直偏右
62%  最高点略停（有「抡」的分量）
92%  落下、插入土中  ← 引擎正好在这一刻产出
100% 锄在土里
```

土粒的关键帧卡在同一段（88%–99%）。**播放顺序对了，玩家看到的是「这一锄挖出来的」**；
顺序反了，就变成「先出东西、人再动一下」，像在放幻灯片。

**三处工程决定**

1. **纯视觉层，零平衡风险**：`scene.js` 不调 `giveItem` / `gainXp` / `addRecord`，
   一条数值也不碰。测试里逐条钉住。
2. **挂在静态节点上，增量更新**：各页都是 `innerHTML` 整块重绘，
   现场若在重绘范围内，动画每渲染一次就归零——等于没动画。
   故 `index.html` 里给一个静态的 `#sceneBar`，只在「场景签名」变化时重建，
   数字变化时只改那一个文本节点。
3. **签名不含计数**：已采几件不进 `sceneSig`，否则每采一次就重建一次，
   挥锄动画会被打断在开头。

**不给计数的地方就不给**

观象、谒见、莳植没有「一件一件出东西」这回事。
摆一个永远是 0 的大数字，比不摆更让人困惑——那几档只写名号。

**能关掉**：设置里「行动现场画面」开关（`Prefs.sceneOn`）。
手机屏高宝贵，82px 是 82px。关掉时整块隐藏，仪表带照常。

**动效关闭时留静帧**：`fxLevel === 'off'` 时画面还在（知道在做什么），只是不动。

**测**：新增第 145 节（42 条），钉住「纯视觉」「周期等于行动间隔」「落下排在周期后段」
「签名不含计数」「不引任何位图」——最后这条是给日后的人看的：
这个项目的 `assets/` 至今只有一个 14KB 字体文件，所有图形都是手写路径。

可采之物里 150 件产于多座山（玉 38 处、金 42 处、梓 15 处），数据里 `nodes[]` 是全部产地，
`node` 只是「主产地」。此前只认 `it.node`，于是站在次产地采东西，会被传送回主产地——
明明脚下就有，为何要走一趟。

**bug 3：积石之山「万物无不有焉」，实际一件也采不到**

`SPECIAL_NODES` 里 7 座山有特殊规则，其中积石之山「万物无不有焉」——引擎放行任何物。
但 UI 按 `nodes[]` 过滤，而积石之山的 `nodes[]` 里一件物都没列（它什么都产，
不需要列清单），于是这个「什么都有」的山，采不了任何东西。

**解法：判据单一来源**

按 ROADMAP 里早就写下的那条规矩（「同一件事只留一处定义」），把判定收成一处：

| 函数 | 管哪一层 | 口径 |
|---|---|---|
| `isGatherSkill` / `GATHER_SKILLS` | 是不是采集之物 | 白名单四门：`qiaocai` `caiyu` `yu` `caiyao` |
| `gatherAllowed` | 能不能采（等级） | 不越级 → 满效；越级 ≤8 → 衰减；>8 → 拒 |
| `gatherAllowedAt` | 此地产不产 | 产地清单命中 / 万物山通吃 / 主产地兜底 |
| `gatherSources` / `gatherHomeNode` | 产地在哪 | `nodes[]` 全集；`node` 仅作主产地与兜底 |
| `gatherReachableNode` | 去哪采 | 在全部产地里挑一处**已解锁**的 |

五处调用点全部改为引用，不再各判各的。

**顺带修的**

- 白名单外的物（有 27 件带 `skill:'lie'` 猎、`'puyi'` 铺艺的异兽）此前会在万物山被列出来，
  点进去崩在 `Skills[it.skill].icon`（技能表里没有这两门）——现在引擎与 UI 一致拦下；
- **解锁属于「能否前往」，不属于「是否产地」**。一开始把 `nodeUnlocked` 塞进 `gatherAllowedAt`，
  结果离线结算（引擎每帧调用）与手动采集被搅在一起，回归了三处。解锁检查退回到
  `startActivity` / `startEntryActivity` 这一层：当前山站得住才就地采，否则挑一处已解锁的产地前往；
- 没有已解锁产地时不再静默失败，明确提示「先开通相应山川」；
- 兜底动作（闲时自动找事做）与离线估算改认全部产地，并认越级衰减；
- 采集弹窗显示当前山而非主产地名，多产地另标「此地亦产」。

**测**：引擎测试新增第 141 节（33 条），把三个修复点与「解锁不进产地判据」钉住。

## v1.31.46 · 2026-10-27

**图鉴检索终于能用中文输入法**

搜索框一敲拼音就输不进去。根因不是输入法，是渲染：`oninput` → `renderCodex()` 把整块
`#content` 的 `innerHTML` 换掉，**输入框连同它的组合态一起被销毁**。拼音在输入法里是
「暂存在 input 里、还没上屏的文本」，节点一没，组合就断，于是每敲一个字母都要从头再打。

改法不是加 `setTimeout` 之类的补丁，而是**不再重建那个 input**：

- 检索拆成「派生状态（`codexView`）→ 五个片段（成就条 / 分类 chips / 检索框 / 计数 / 网格）」，
  `renderCodex()` 拼装，`patchCodexList()` 只换 `#codexGrid`、`#codexTabs` 与计数；
- 输入时走 patch，输入框原地不动 —— 焦点、光标、组合态全部自然保留；
- 组合期间连列表都不刷（`compositionstart` 期间只记下 `codexQuery`），上屏后再筛；
- 分类 chips 外面包一层 `#codexTabs`，用 `display:contents` 让包装层不参与布局，
  换行与间距和原来一模一样。

**一个踩到的坑值得记下来**：监听器最初写成行内 `oncompositionstart="…"`，浏览器里
`'oncompositionstart' in window` 是 false（并非所有内核都实现了这个 IDL 属性），
行内写法等于没写——组合事件一个都收不到。改为 `addEventListener` 绑定（`bindCodexSearch`），
不依赖 IDL 属性。已在 `docs/ROADMAP.md` 技术债里记一条。

**墟市：把「售价走势」那根线撤了**

那个角落图信息量太低：一条倍率曲线，既不说明「为什么涨」（倍率只受商旅等级 / 营造 /

价差）再重画，那时的图该画的是价差，不只是倍率。

采集此前是「一点就一直采」，要「采 20 次就去巡历」只能盯着一遍遍手动停。讨伐早就有

## v1.31.44 · 2026-10-26

**兽名不再是一个圈：随项目分发 41 字子集字体**

玩家报「部分兽没有具体名字，显示成一个圈圈」。查下来不是数据缺名，是**缺字形**：

- 异兽名里有 15 只用到了 CJK 扩展 B 区的字（𧔥 𪁺 𪁸 𩽵 𩇯 𤛎 𢓭 𤟤 …），码位在 U+20000 以上；
- 而 UI 的字体栈是 `PingFang SC / HarmonyOS Sans / 思源黑 / Noto CJK` —— **没有一个收这些码位**，
  浏览器只能画豆腐块（不同系统显示为 □ / ○ / ?，用户看到的就是「圈」）；
- 系统层无解：Windows 只有 SimSun-ExtB 覆盖一部分，Android / iOS 几乎全缺。

做法是**随项目分发一份只含这些字的子集字体**：

| 项 | 值 |
|---|---|
| 来源 | 花园明朝 HanaMinB（GlyphWiki），Hanazono Font License / OFL 1.1 |
| 字符 | 41 个（数据里全部 U+20000+ 的汉字，含物品名与原文引文用到的） |
| 体积 | **14KB** woff2 |
| 挂载 | `@font-face` + **精确列出**的 `unicode-range`，接在 `--f-song` / `--f-sans` 末尾 |
| 单文件版 | 构建时内联为 base64；产物残留 `assets/` 引用即构建失败 |

一个坑值得记：`unicode-range` **不能**写成 `U+20000-2A6DF`。
那样浏览器会以为本字体覆盖整个扩展 B 区，遇到别的扩展字也选它，取不到字形照样豆腐 ——
比不加还糟。必须逐个码位列出来。

另一个细节：`size-adjust:106%`。明朝体在同等 em 下字面比黑体小一号，混排会显得「缩了一头」，
这条只作用于这 41 个字，把字面补回来。

配套：
- `assets/LICENSE_ASSETS.md` 按项目纪律登记（原先写着「本期为空」，现在有第一条了）；
- 测试第 134 节钉**覆盖性**：遍历 `CODEX / Items / Monsters` 里所有 U+20000+ 的字符，
  每一个都必须落在 `unicode-range` 内 —— 将来加了新的生僻字名却忘了重做子集，这条当场报出来。

### 审查发现并修掉的三处

**1. 非战斗时吃食物：扣了物品，没回血，还提示「回血 40」**
