## v1.31.103 · 2026-10-27

**旧档升级实测：能读，但结构会「越攒越歪」。**

这一小时加了 `events.awayAt` / `events.lastAt` 两个字段。你手机上那份存档是旧结构，
所以专门做了一次端到端验证：造一份「v1.31.85 时代」的档（`events` 只有
`at / count / lastId / seen`），删掉新字段，重新加载。

结果：**能读，数值全对**（贝币 12345、樵采 40 级、行囊 30 件、见闻计数 3+1），
统计页正常，0 报错——因为所有新字段的读法都是 `st.awayAt || 0`。

但发现一个隐患：读档后 `Game.events` 里**依然没有这两个键**。功能靠 `|| 0` 兜着，
可下次 `saveGame()` 又会把这份不完整的结构原样写回去，如此循环。
「靠兜底能跑」和「结构是对的」是两件事，前者会让后者永远不修。

改成默认值打底再合并：

```js
Game.events = Object.assign({ at: 0, count: 0, lastId: '', seen: {}, awayAt: 0, lastAt: 0 },
                            (d.events && typeof d.events === 'object') ? d.events : {});
```

旧值仍然优先（`Object.assign` 后写的覆盖先写的），只是缺的字段被补齐。
全站 3166 条通过，`--full` 全绿。

## v1.31.99 · 2026-10-27

**核对「文案说的数字 = 账上的数字」。**

见闻给的是「一句文案 + 一点东西」。文案写着「贝 +80」，账上就必须是 +80。
这两者一旦漂移，玩家基本发现不了——数字小、又不进统计口径——
但「说的话不算数」恰恰是这类小事件最伤人的失败模式。

第 178 节的做法是把文案当契约：跑一遍 `run()`，从日志里用正则把「贝 +N」
与「某某 +N」抽出来，和实际增量逐条对账：

- 贝：`/贝 \+(\d+)/` 抽出的数，必须等于 `Game.shells` 的增量，
  且必须计入 `stats.totalEarned`（否则统计页的收入曲线会漏）
- 经验：文案里所有 `+N` 之和，必须等于 `stats.totalXp` 的增量（容差 ±1）

**第一版写错了**：抽经验时没把「贝 +N」剔出去，于是「残简（著录 +9 · 贝 +10）」
被判成 21 经验——四条全红。剔掉贝币的片段之后全绿。

这条测试的价值不在今天（现在六条都对得上），在于以后调数值时：
改了 `run()` 里的公式却忘了改文案，它会红。

全站 3160 条通过，`--full` 全绿。

## v1.31.98 · 2026-10-27

**见闻不再总是那一条：抽取分「见过 / 没见过」两层。**

18 条见闻 + 90 秒冷却 = 挂一小时能撞三十多次。同一条反复出现，
玩家记住的会是「又是残简」，而不是「这本书里有多少种事」。

**第一版做错了，值得记下来。** 我按「已见次数给权重打折」（`w / (1+0.6n)`），
但珍稀（`weight: 1`）不参与打折——于是别人都降到 0.23 时，它以 1 独占 53%
（实测 300 次抽样：159 条「古碑可读」）。**「珍稀」变成了「最常见」。**
这是「局部正确、整体错位」的典型：每一行都对，组合起来语义反了。

改成**分层抽取**：不碰权重，只调「从哪一层抽」。65% 走「没见过」那层，
35% 走全池——留一点给旧句子，否则见全之后就只剩稀有两条在转。

## v1.31.74 · 2026-10-27

### 一、「滑动时出现横向滚动」的真因不是溢出

第一反应是找溢出的元素，结果四档宽度（320/360/390/430）× 13 页 × 边滚边采样 25 次，
`scrollWidth - clientWidth` **全是 0**——页面本身没有溢出。

真因是 iOS Safari 的一条老规矩：**输入框字号 < 16px 时，一聚焦就把页面放大（约 1.33 倍）**。
放大之后整页可以左右拖，看起来就像「滚动时溢出」。这也解释了为什么只有
「部分页面」有——图鉴与行装各有一个检索框，设置页有昵称与云端地址。

`overflow-x:hidden` 拦不住它：那是**视觉视口**的缩放，不是 CSS 溢出。

| 处 | 之前 | 现在 |
|---|---|---|
| 检索框（图鉴 / 行装） | 12px | 16px |
| 设置页输入框 | 15px | 16px |
| 数量框 / 淬炼框 | 13 / 11.5px | 16px |

顺带给 `body` 加了兜底：`overflow-x:hidden` → `overflow-x:clip`。
**用 clip 不用 hidden**：hidden 会把 body 变成滚动容器，里面的 `position:sticky`
（顶栏、图鉴分类条）会跟着失效；clip 不建立滚动容器。两行都写，
认 clip 的按 clip 来，老内核退回 hidden。

### 二、为什么没做「整页 scale 缩放」

你提的方案是把界面按固定宽度渲染，再整体缩放到屏幕宽。它能消掉横滚，但代价很大：

- **字会糊**：非整数倍缩放（390→430 是 1.10 倍）会让 13.5px 的字落在半像素上；
- **杀掉双指放大**：本来就看不远的字，再也没法凑近看；
- **fixed 元素错位**：顶栏、抽屉遮罩、浮层都以缩放后的坐标系计算，`100vh` 尤其容易裂；
- **治不了根**：iOS 的聚焦放大照旧发生，只是把「放大后的页面」也一起缩了。

这次的改法是从源头去掉缩放（字号），再加一道不产生副作用的兜底（clip）。

### 三、设置页新增「强制刷新 · 重载最新版」

点一下：清 Cache API → 注销 Service Worker → **先存档** → 带 `_r=<时间戳>` 重载整页。

主屏幕里的独立实例最顽固，连 `index.html` 都可能一直用旧的；这颗按钮是给它准备的。
**不碰 localStorage**——那是存档，清缓存不该把进度一起清掉（已写成断言锁住）。

做法一样：先画一屏多，底下放一颗「还有 N 条 · 展开」。点它放 120 条，

- 换分类、换筛选、换排序、换检索词，都会把分页重置回第一屏（`codexLimit = 0`）。
  否则「筛到 3 条却还停在 120 的上限」会让人以为筛选没生效。

> 这一处不是「优化」，是「手机上的卡顿」：152ms 的切页已经是掉帧级别，
> 而中端安卓机上还要再乘一倍。分页之后才回到「点一下就出来」的手感。

## v1.31.59 · 2026-10-31

**「Safari 里直接开有动画，添加到桌面就没有」**

这条反馈比「丑」有用得多——它把问题从审美拉回了工程。

### 根因：自调度写在了 rAF 回调的开头

```js
const step = ()=>{
  UI._sceneRaf = requestAnimationFrame(step);   // ← 先排下一帧，再干活
  ...
};
```

iOS 把「添加到主屏幕」的网页放进独立 WebView，切后台/挂起时会把**已排队但未执行**
的回调直接丢掉。丢一次，链就断了。更糟的是 `UI._sceneRaf` 里还留着那个死掉的 id，
而重启的判据是：

```js
if (UI._sceneRaf) return;    // id 非 0 就当成「还在跑」
```

于是**永远不再启动**——一条死链把唯一的救活入口也锁死了。桌面浏览器里切标签页
通常不会丢回调，所以只在手机独立模式下复现。

### 四处一起改

| 改动 | 为什么 |
|---|---|
| 自调度挪到 `finally` 里、画完再排 | 一帧被丢，最多丢一帧，链自己接得上 |
| 切后台主动收链，回来重开 | 不让系统有机会「挂着一个待执行的回调」 |
| 用**心跳**（`_sceneLast` 时间戳）判断是否还在跑 | id 非 0 不等于活着；超过 1.2s 没出帧就重启 |
| watchdog 每秒看一眼，连试三次救不回来就降级 CSS | 环境压根不给 rAF 时也得动 |

### 降级层：转 div，不转 `<g>`

`#sceneBar.fx-css .sc-stage` 用 `scFallback` 关键帧绕握点转。转的是一个 **div**，
不是 SVG 图形元素——这是三次「手机不动」换来的教训里最硬的一条。
降级后相位只按墙钟走、与产出不同步，但「在动」比「准却不动」要紧。

### 诊断搬进设置

`?probe=1` 在独立模式下用不了（没有地址栏）。设置页新增「现场诊断」开关，
左下角一行显示 `帧 N · 相位 x · 间隔 ys · 迟 ms · 谁在驱动`：
帧数不涨 = JS 没跑；迟 = 停 = 链断了；`CSS（JS 停摆）` = 已降级。

## v1.31.56 · 2026-10-30

**手机端：两版都没动**

v1.31.54 上线，用户说「没看见动画」；v1.31.55 加大幅度、加全身俯仰，用户说「手机上还是没动」。
两次我都在桌面 Chromium 里采样变换矩阵，数值确实在变——**这说明我的验收方式本身有问题**。

**换掉驱动方式，不再赌内核**

前两版依赖两条 CSS 路径：

1. `SVG <g>` 上的 CSS `transform` — 部分移动端内核对不齐；
2. `animation` 简写里带 `var(--ai)` — 简写属性里塞 CSS 变量，解析失败的引擎会直接丢弃整条声明。

与其逐条猜哪条没生效，不如换成最土的办法：

**一个 HTML 元素 + 一条内联 `transform`，每帧由 JS 写。**

具体改了三处：

| 项 | 之前 | 现在 |
|---|---|---|
| 锄头所在 | 人物 SVG 内部的 `<g class="sc-tool">` | **独立的 `<svg class="sc-tool">`**，绝对定位在握点 |
| 旋转来源 | CSS `@keyframes scSwing` | `UI.startSceneMotion()` 里的 `requestAnimationFrame` |
| 时长来源 | `animation-duration: var(--ai)` | 每帧直接算，不经过 CSS |

**顺带得到的好处：相位不再另建时间基准**

角度不是按「页面打开后过了几秒」算，而是按**引擎自己的进度**：

```
p = activityProgress / currentActionInterval()
```

于是暂停、变速、换物、离线补算回来之后，锄头永远落在正确的相位上——
「第二锄落下 = 产出物品」这条因果，从此不依赖任何定时器对齐。

**角度的两张帧表**

| 帧位 | 工具角度 | 身体角度 |
|---|---|---|
| 0% | +6° | 0° |
| 15% | −98° | −2.2° |
| 29% | +4° | +3.2° |
| 56% | −114° | −2.6° |
| **92%** | **+4°（产出）** | **+3.6°** |
| 100% | +6° | 0° |

分段插值里加了缓动——纯线性的挥动像机械臂。

**验证方式也换了**

不再只看「动画名对不对」，而是：**注入 `*{ animation: none !important }` 把整页 CSS 动画全部禁掉，再看锄头还动不动。**

结果：六次采样六个不同角度（−77° → −17° → +4° → +6° → −39° → −97°）。
**CSS 全禁之后仍在动**——因为驱动它的是 JS 和一条内联 transform。

**再加一层兜底：拿不到进度就按墙钟走**

相位本来取 `activityProgress / interval`。这是跨 script 读的顶层 `let`——
正常环境没问题，但万一某个环境读不到，相位会恒为 0，锄头就定在那儿。
所以加了一行：读不到就退化为 `performance.now() % 周期 / 周期`。
**宁可相位与产出的对齐略有偏差，也不能定住不动。**

**测**：第 145 节改指新实现，新增「工具不在人物 SVG 内部」「每帧写内联 transform」
「相位取 activityProgress / interval」「CSS 里不再有挥锄动画」等断言。
引擎测试 2665 通过 / 0 失败。

**上线当天用户反馈：「没有看见动画效果」**

**改法**

| 项 | 之前 | 现在 |
|---|---|---|
| 挥锄频率 | 一个周期 1 锄 | **2 锄**（第一锄松土、第二锄出土） |

所以把人包进一层 `<div class="sc-rig">` 做整体 rotate：**div 上的 transform 是所有内核都吃的**。
最坏情况是锄头不动、人还在晃，总比整块静住强。

|---|---|

**一条必须对齐的因果**

锄头落下的时刻，必须就是引擎产出物品的时刻。

所以挥锄动画的周期不用固定值，而是 `animation-duration: var(--ai)`，
`--ai` 直接取 `currentActionInterval()`——采集间隔多长，挥一次就多久。
帧序也刻意把「落下」排在周期的 92%（而不是开头）：

```
0%   锄在土里
46%  举到竖直偏右
62%  最高点略停（有「抡」的分量）
92%  落下、插入土中  ← 引擎正好在这一刻产出
100% 锄在土里
```

土粒的关键帧卡在同一段（88%–99%）。**播放顺序对了，玩家看到的是「这一锄挖出来的」**；
顺序反了，就变成「先出东西、人再动一下」，像在放幻灯片。

**三处工程决定**

1. **纯视觉层，零平衡风险**：`scene.js` 不调 `giveItem` / `gainXp` / `addRecord`，
   一条数值也不碰。测试里逐条钉住。
2. **挂在静态节点上，增量更新**：各页都是 `innerHTML` 整块重绘，
   现场若在重绘范围内，动画每渲染一次就归零——等于没动画。
   故 `index.html` 里给一个静态的 `#sceneBar`，只在「场景签名」变化时重建，
   数字变化时只改那一个文本节点。
3. **签名不含计数**：已采几件不进 `sceneSig`，否则每采一次就重建一次，
   挥锄动画会被打断在开头。

**不给计数的地方就不给**

观象、谒见、莳植没有「一件一件出东西」这回事。
摆一个永远是 0 的大数字，比不摆更让人困惑——那几档只写名号。

**能关掉**：设置里「行动现场画面」开关（`Prefs.sceneOn`）。
手机屏高宝贵，82px 是 82px。关掉时整块隐藏，仪表带照常。

**动效关闭时留静帧**：`fxLevel === 'off'` 时画面还在（知道在做什么），只是不动。

**测**：新增第 145 节（42 条），钉住「纯视觉」「周期等于行动间隔」「落下排在周期后段」
「签名不含计数」「不引任何位图」——最后这条是给日后的人看的：
这个项目的 `assets/` 至今只有一个 14KB 字体文件，所有图形都是手写路径。

## v1.31.48 · 2026-10-29

**「能不能采」这件事，此前在五个地方各写了一遍**

采集是这游戏最基础的动作，可判定「能不能采」的规则却散在五处：引擎的 `doGather`、
手动采集的 `startActivity`、队列采集的 `startEntryActivity`、舆地的按钮渲染、离线结算。
每处各写各的，于是同一件事有了五个口径——这轮修的三个 bug，全是口径打架打出来的。

**bug 1：舆地标着「越级 84% 可采」，点下去被弹回**

引擎 `doGather` 允许越 8 级硬采（效率按 `max(0.35, 1 - gap×0.08)` 衰减），
但 `startActivity` 是一道硬门槛——等级不足直接 `return false`。玩家看到的明明写着可采，
点下去毫无反应。两处对同一件事的判断必须一致。

**bug 2：站在合法产地，却被传送回「主产地」**

可采之物里 150 件产于多座山（玉 38 处、金 42 处、梓 15 处），数据里 `nodes[]` 是全部产地，
`node` 只是「主产地」。此前只认 `it.node`，于是站在次产地采东西，会被传送回主产地——
明明脚下就有，为何要走一趟。

**bug 3：积石之山「万物无不有焉」，实际一件也采不到**

`SPECIAL_NODES` 里 7 座山有特殊规则，其中积石之山「万物无不有焉」——引擎放行任何物。
但 UI 按 `nodes[]` 过滤，而积石之山的 `nodes[]` 里一件物都没列（它什么都产，
不需要列清单），于是这个「什么都有」的山，采不了任何东西。

**解法：判据单一来源**

按 ROADMAP 里早就写下的那条规矩（「同一件事只留一处定义」），把判定收成一处：

| 函数 | 管哪一层 | 口径 |
|---|---|---|
| `isGatherSkill` / `GATHER_SKILLS` | 是不是采集之物 | 白名单四门：`qiaocai` `caiyu` `yu` `caiyao` |
| `gatherAllowed` | 能不能采（等级） | 不越级 → 满效；越级 ≤8 → 衰减；>8 → 拒 |
| `gatherAllowedAt` | 此地产不产 | 产地清单命中 / 万物山通吃 / 主产地兜底 |
| `gatherSources` / `gatherHomeNode` | 产地在哪 | `nodes[]` 全集；`node` 仅作主产地与兜底 |
| `gatherReachableNode` | 去哪采 | 在全部产地里挑一处**已解锁**的 |

五处调用点全部改为引用，不再各判各的。

**顺带修的**

- 白名单外的物（有 27 件带 `skill:'lie'` 猎、`'puyi'` 铺艺的异兽）此前会在万物山被列出来，
  点进去崩在 `Skills[it.skill].icon`（技能表里没有这两门）——现在引擎与 UI 一致拦下；
- **解锁属于「能否前往」，不属于「是否产地」**。一开始把 `nodeUnlocked` 塞进 `gatherAllowedAt`，
  结果离线结算（引擎每帧调用）与手动采集被搅在一起，回归了三处。解锁检查退回到
  `startActivity` / `startEntryActivity` 这一层：当前山站得住才就地采，否则挑一处已解锁的产地前往；
- 没有已解锁产地时不再静默失败，明确提示「先开通相应山川」；
- 兜底动作（闲时自动找事做）与离线估算改认全部产地，并认越级衰减；
- 采集弹窗显示当前山而非主产地名，多产地另标「此地亦产」。

**测**：引擎测试新增第 141 节（33 条），把三个修复点与「解锁不进产地判据」钉住。

## v1.31.46 · 2026-10-27

**图鉴检索终于能用中文输入法**

搜索框一敲拼音就输不进去。根因不是输入法，是渲染：`oninput` → `renderCodex()` 把整块
`#content` 的 `innerHTML` 换掉，**输入框连同它的组合态一起被销毁**。拼音在输入法里是
「暂存在 input 里、还没上屏的文本」，节点一没，组合就断，于是每敲一个字母都要从头再打。

改法不是加 `setTimeout` 之类的补丁，而是**不再重建那个 input**：

- 检索拆成「派生状态（`codexView`）→ 五个片段（成就条 / 分类 chips / 检索框 / 计数 / 网格）」，
  `renderCodex()` 拼装，`patchCodexList()` 只换 `#codexGrid`、`#codexTabs` 与计数；
- 输入时走 patch，输入框原地不动 —— 焦点、光标、组合态全部自然保留；
- 组合期间连列表都不刷（`compositionstart` 期间只记下 `codexQuery`），上屏后再筛；
- 分类 chips 外面包一层 `#codexTabs`，用 `display:contents` 让包装层不参与布局，
  换行与间距和原来一模一样。

**一个踩到的坑值得记下来**：监听器最初写成行内 `oncompositionstart="…"`，浏览器里
`'oncompositionstart' in window` 是 false（并非所有内核都实现了这个 IDL 属性），
行内写法等于没写——组合事件一个都收不到。改为 `addEventListener` 绑定（`bindCodexSearch`），
不依赖 IDL 属性。已在 `docs/ROADMAP.md` 技术债里记一条。

**墟市：把「售价走势」那根线撤了**

那个角落图信息量太低：一条倍率曲线，既不说明「为什么涨」（倍率只受商旅等级 / 营造 /
御使 / 征兆影响，都写在明面上），也指导不了任何决策。连它每秒的采样（`priceHistory`）
一并删除——没人读的数组不必每秒比较一次。等专门的经济系统做起来（供需、囤货、跨区域
价差）再重画，那时的图该画的是价差，不只是倍率。

**舆地：采集也能设次数了**

采集此前是「一点就一直采」，要「采 20 次就去巡历」只能盯着一遍遍手动停。讨伐早就有
∞ / 1 / 5 / 10 / 50 的场次设置，**同一类动作却是两套规矩**。

- 采集按钮改为先开弹窗（与讨伐弹窗同一个版式：次数输入 + 快选 chips + 换算说明）；

- 而 UI 的字体栈是 `PingFang SC / HarmonyOS Sans / 思源黑 / Noto CJK` —— **没有一个收这些码位**，
  浏览器只能画豆腐块（不同系统显示为 □ / ○ / ?，用户看到的就是「圈」）；
- 系统层无解：Windows 只有 SimSun-ExtB 覆盖一部分，Android / iOS 几乎全缺。

做法是**随项目分发一份只含这些字的子集字体**：

| 项 | 值 |
|---|---|
| 来源 | 花园明朝 HanaMinB（GlyphWiki），Hanazono Font License / OFL 1.1 |
| 字符 | 41 个（数据里全部 U+20000+ 的汉字，含物品名与原文引文用到的） |
| 体积 | **14KB** woff2 |
| 挂载 | `@font-face` + **精确列出**的 `unicode-range`，接在 `--f-song` / `--f-sans` 末尾 |
| 单文件版 | 构建时内联为 base64；产物残留 `assets/` 引用即构建失败 |

一个坑值得记：`unicode-range` **不能**写成 `U+20000-2A6DF`。
那样浏览器会以为本字体覆盖整个扩展 B 区，遇到别的扩展字也选它，取不到字形照样豆腐 ——
比不加还糟。必须逐个码位列出来。

另一个细节：`size-adjust:106%`。明朝体在同等 em 下字面比黑体小一号，混排会显得「缩了一头」，
这条只作用于这 41 个字，把字面补回来。

配套：
- `assets/LICENSE_ASSETS.md` 按项目纪律登记（原先写着「本期为空」，现在有第一条了）；
- 测试第 134 节钉**覆盖性**：遍历 `CODEX / Items / Monsters` 里所有 U+20000+ 的字符，
  每一个都必须落在 `unicode-range` 内 —— 将来加了新的生僻字名却忘了重做子集，这条当场报出来。

### 「强化至 +N」现在会告诉你花多少

+20 之后一次就要几十万贝，玩家原先只能点下去才知道贵。

  两处渲染（首屏 / 展开）走同一函数。数据侧确认蛊雕只有一处产地：鹿吴之山。
