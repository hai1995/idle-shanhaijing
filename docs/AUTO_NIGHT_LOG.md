### 夜间总结

**共 18 次提交。最大收益项是「坏档锁页」**——存档里一条缺 `skill` 的采集行动，
会让 `currentActivityLabel` 每次重绘都抛错，舆地与技能两页从此整页白掉。
这类错玩家只会描述成「游戏坏了」，而且刷新也修不好（错在存档里）。

**第二收益项是「现场停不掉」**：`stopSceneMotion()` 只 `cancelAnimationFrame`，
拦不住正在执行的那一帧——它末尾又排下一帧，于是关掉画面后仍在后台每帧跑。
发现路径很绕：做场景注册表重构时想用像素比对证明「画面没变」，
结果同一场景两次抓图总有几十个像素不同；追下去不是渲染不稳，是基准图本身在动。

**最需人工确认项仍是「现场画人」的方向**：六种行动共用同一个小人，
40px 下已经到这套手写 SVG 的极限。要再好看只能上美术资源（序列帧/剪影），
这是资源决策，不是代码决策——上一轮留的 A/B/C/D 四个方向还没选。

### 这一夜真正的收获不是这几个补丁，是四条能复用的判据

1. **同一件事有两个写法时，先查「历史遗留的第二份」**
   数字有 `fmt()`（K/M/B）与 `fmtNum()`（万/亿），时长有 `fmtTime()`（无「天」）与 `fmtDur()`（有「天」）。
   两处都是「后加的没回头看先有的」。收的时候连同边界一起收：9999.99 万 该说 1 亿，
   999999 不该说 1000.0K。
2. **注释里的旧数字比没有注释更糟**
   ARCHITECTURE 写「26 个 script」而实际 27 个、TESTING 写「2027 条断言」而实际两千七，
   `ui.js` 早拆成 8 个文件。这次既改了数，也加了两条守卫（脚本数、文件表覆盖），
   并把「会过期的数字」从 TESTING 里整段拿掉。
3. **验证重构，「看起来一样」不算证据**
   这次把 6 种行动 × 2 个主题的 `sceneHtml` 输出逐字符比对，12/12 相同——
   比截图比对可靠得多。而截图比对的价值在另一处：它逼出了一个真 BUG。

4. **发版流程的每一步都该有一条会变红的断言**
   `?v=` 漏改的症状是「本地好了、手机上没好」，为它白查过三轮。
   现在测试盯着：每个本地资源必须带 `?v=` 且等于 package.json 的版本。

### 这一小时真正的收获，是三条关于「怎么判断」的

1. **「机制测过了」不等于「内容够用」。** 见闻的冷却、概率、落档全被 167 节锁死，全绿；
   但玩家实际看到的是「采药 +9」重复十四次。分布问题测不出来——只能摊开看
   「谁在什么场景下能抽到哪几条」。这次把断言对象换成**候选池**而不是随机结果。

2. **先量稳态，再谈优化。** 我第一次量只看「首次」，把技能页 197ms 归因到 26 份隐藏浮层，
   改完只降到 177——那一整块改动没打到点子上。补量稳态，真正的瓶颈（墟市 155、御使 132）
   立刻浮出来，两处改完各降 6-7 倍。**首次那一列只回答「第一次打开会不会卡」。**

3. **一处漏了，说明是结构不是手滑。** `events.js` 没进脚本清单，先在审计红一次，
   补完压测又红一次。第二次才动手把守卫做成通用的（扫 `scripts/` 下所有清单）。

4. **局部都对，组合起来可能语义反了。** 「见过的降权」这条每一行都对，跑 300 次抽样才发现：
   珍稀不参与打折，于是别人降到 0.23 时它以 1 独占 53%——「珍稀」成了「最常见」。
   这类错误测不出来（单条权重函数完全正确），只能跑一遍看分布。**规则之间会互相作用，
   而这个作用通常不在你写下的那条注释里。**

另外两条小坑：用 `.sc-wrap{` 当 CSS 插入锚点，命中了 `[data-theme="night"] .sc-wrap{` 内部，
把夜间选择器劈成两半（页面不报错，测试红的）；搬代码搬出两处语法错误，
VM 里整个文件一起崩、报错位置还指在别处——**搬完先跑 dump，不要先看 diff**。

### 没做的事（有意）

- 没动任何平衡数值：经验曲线、怪的血攻、强化概率、祠礼成本全部原样。
- 没碰现场「画人」的造型（40px 下已到这套手写 SVG 的极限，要更好只能上美术资源）。
- 云端存档与账号系统仍未开工（按项目主定，等账号系统）。

- 顺手扫到一处真的：`save.js` 的 `window.flushCloudSave = function(){...}`，
  而 **`boot.js` 在 `pagehide` / `visibilitychange` 里裸名调用它**。

- 用一个小实验把机理钉死（值得记）：
  ```js
  function declaredFn(){}           // 裸名 → 'function'，ctx.declaredFn 也是 function
  window.exprFn = function(){};     // 裸名 → 'undefined'，ctx.exprFn 也是 undefined
  ```
  差别不在「挂没挂 window」，而在**表达式赋值不产生全局变量**。
  所以规矩是：**跨文件共享的函数，一律先写函数声明，再挂 window**。

  扫描面必须与 `index.html` 的脚本数一致（39 = 39），漏扫一个文件就等于给那文件开后门。

## v1.31.137（本轮第 38 批）· 11 个 NaN

- 换了个方向查鲁棒性：把统计数值全塞成 `NaN` / `Infinity`，逐页渲染看会怎样。
  结果统计页直接写出 **11 个「NaN」和 1 个「Infinity 天」**。
- 根因有三层，每层都不同：
  1. `patchStats` 里大量 `String(s.kills)` —— `String(NaN)` 就是 `"NaN"`，原样进 DOM；
  2. `fmtDur` 用 `sec || 0` 兜底 —— 对 `NaN` 有效（NaN 是假值），但对 `Infinity` **无效**
     （真值），于是 `Math.round(Infinity)` → `Infinity` → 输出「Infinity 天」；
  3. `fmtNum` 用 `Number(v) || 0` —— 同样的漏洞，会输出「Infinity 亿」；
     而 `seasonRemainSec` 对 `Infinity` 取模得 `NaN`，文案变成「NaN 分」。
- 修法分两处，是为了让责任清楚：
  - **显示层统一归一**：`sanitizeStats()` 把一层数值 + 一层嵌套计数表里的
    非有限值变 0，统计页静态渲染与 800ms 的 patch **共用这一份**。放在显示层而不是
    写入处，是因为数值来自几十处计算，逐个加守卫既啰嗦又必然漏；且它返回浅拷贝，
    `Game.stats` 本体不动，不掩盖存档里的真实值。
  - **格式化函数各自兜底**：`fmtNum` / `fmtDur` 改用 `safeNum`。
    关键点是 `Number.isFinite` 而不是 `Number(v) || 0` —— 后者对 `Infinity` 返回真值，
    正是这次漏网的原因。
- 写测试时被项目自带的一条断言拦住：「无既未调用也未导出的顶层函数（game.js:sanitizeStats）」。
  这个仓库早就有一条死代码检查，新函数忘了挂 window 会被它抓出来——省了我一次线上排查。
- 第 192 节 8 条断言，其中两条**最初是失败的**（`fmtDur(Infinity)`、`fmtNum(Infinity)`），
  反向验证也做了：把 `safeNum` 改回 `Number(v) || 0`，立刻报「Infinity 亿」。
- 巡检加「坏数据」检查（34 组）：注入 NaN → 逐页渲染 → 断言文本里没有
  `NaN` / `Infinity` / `undefined`。反向验证：去掉统计页的归一，
  两个视口都报「stats:NaN×10；顶栏:NaN×10」。
- 验收：3445 断言全绿（+27）；`check.js --patrol` 七步全过；巡检 34 组 0 坏；
  线上 v1.31.137 已确认。
