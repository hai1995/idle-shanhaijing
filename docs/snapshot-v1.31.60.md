## 一、v1.31.59：现场驱动自愈

**用户原话**：「我直接在 Safari 上访问，有动画，但我将其添加到桌面的，他就没有动画。」

这条比「丑」有用得多——它把问题从审美拉回了工程。

### 根因

```js
const step = ()=>{
  UI._sceneRaf = requestAnimationFrame(step);   // ← 先排下一帧
  ...
};
...
if (UI._sceneRaf) return;                       // ← 用 id 判断「还在跑」
```

iOS 把「添加到主屏幕」的网页放进独立 WebView，挂起时会把**已排队但未执行**的回调丢掉。
丢一次链就断；而 `_sceneRaf` 里还留着死掉的 id，重启入口被自己锁死——**永远不再启动**。
桌面浏览器切标签页一般不丢回调，所以只在手机独立模式复现。

### 四处一起改

| 改动 | 为什么 |
|---|---|
| 自调度挪进 `finally`、画完再排 | 丢一帧最多丢一帧，链接得上 |
| 切后台主动收链，回前台重开（visibilitychange / pageshow / focus） | 不给系统「挂着待执行回调」的机会 |
| 用**心跳**（`_sceneLast`）判断生死，超 1.2s 没出帧就重启 | id 非 0 不等于活着 |
| watchdog 每秒看一眼，连试三次救不回来 → 降级 CSS | 环境压根不给 rAF 也得动 |

### 降级层

`#sceneBar.fx-css .sc-stage` 用 `scFallback` 关键帧绕握点转。转的是 **div**，不是 `<g>`——
这是三次「手机不动」里最硬的一条教训。降级后相位只按墙钟走、与产出不同步，
但「在动」比「准却不动」要紧。

### 诊断搬进设置

`?probe=1` 在独立模式下用不了（没有地址栏）。设置页新增「现场诊断」，
左下角一行：

```
帧 11 · 相位 0.32 · 间隔 3.55s · 迟 停 · CSS（JS 停摆）
```

| 读数 | 含义 |
|---|---|
| 帧数不涨 | JS 没跑（或加载的是旧版） |
| 迟 一直在涨 | 链断了，watchdog 没救回来 |
| CSS（JS 停摆） | 已降级，在动但不同步 |

### 验收（WebKit 实测）

| 场景 | 结果 |
|---|---|
| 正常 | 帧 25 → 75 |
| 人为 `cancelAnimationFrame` 掐断（id 仍非 0） | 0.6s 内不动 → 3.8s 后帧数恢复 |
| `requestAnimationFrame` 置空 | 自动挂 `fx-css`，`transform` 两次采样不同 |

## 二、v1.31.60：指引条不再是三等价

顺手在 430px 下量各页版面，发现除舆地外每页顶上那条指引，正文只剩 101px：

```
图标 101 · 正文 101 · 前往 101      ← .hint-banner span{flex:1}
```

于是每条都读成「先从『舆地』选山，点其中一项…」，后半句永远看不见。
一条天天在眼前、却永远说不完整话的提示，比没有更烦。

改成只让正文伸缩（图标 15px、前往 28px、正文 259px），两行能放下了。

**规律**：`flex:1` 要写在「该伸缩的那一格」上，不能写给「所有 span」。

## 三、给主屏幕的那一份怎么验

1. 删掉旧图标，用 Safari 打开 → 分享 → 添加到主屏幕（独立实例的缓存比标签页顽固）；
2. 进「设置 → 现场诊断」打开；
3. 看现场左下角：帧数在涨 = 好了；不涨且「迟」一直涨 = 还有问题，把那一行截图。
