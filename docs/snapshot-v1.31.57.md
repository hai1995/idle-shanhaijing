## 本轮一句话

第三次「手机不动」。这次先装了 WebKit（Safari 的引擎）在真内核上测——
**测出来我上一轮的归因是错的**，然后同时处理了三件事。

## 先纠正一个判断

上一轮我以为是「Safari 不支持 SVG 元素的 CSS transform」。在 WebKit 上实测：

| 测什么 | 结果 |
|---|---|
| `<g>` 写 CSS `transform: rotate(45deg)` | 包围盒 40×40 → 56.6×56.6，**生效** |
| `<svg>` 根元素写 CSS `transform` | 80×80 → 113.1×113.1，**生效** |
| `<div>` 写 CSS `transform`（对照） | **生效** |

**Safari 是支持 SVG 的 CSS transform 的。** 前两次的归因都不成立——
所以前两次的「修复」自然也没解决用户的问题。

## 那真正的原因可能是什么

**缓存。** GitHub Pages 给静态资源响应的是 `Cache-Control: max-age=600`——10 分钟。
玩家在推送后立刻刷新，浏览器直接用本地副本，**根本没请求新文件**。

前两版改的东西，用户手机上可能一次都没到过。

这条无法从服务器端验证（我这边每次都是全新上下文，永远拿到最新），
但它能同时解释「三次都不动」和「我这边每次都在动」。

## 三件事一起做

**① 绕开 transform——不是「更兼容」，是「不需要兼容」**

每帧算锄头的两个端点，写 `path` 的 `d`：

```
握点 (30,38) 固定
柄末端 = 握点 + R(角度) · (11,28)
刃     = 末端 ± 垂直方向 × 5.4
```

`d` 是 SVG 1.1 的核心属性，没有内核会不支持。

**② 所有资源加版本串**

`index.html` 里 27 个 `src="src/*.js"` 与 `style.css` 全部带 `?v=1.31.57`。
每次发版改这个串，浏览器就必须重新取文件。
构建脚本与测试里解析清单的正则也一并改成允许 `?v=`。

**③ 加自查入口 `?probe=1`**

三次隔着屏幕猜，代价太高。现在：

```
https://hai1995.github.io/idle-shanhaijing/index.html?probe=1
```

现场条左下角会出现一行小字：`帧 130 · 相位 0.78 · 间隔 3.25s`

| 现象 | 判断 |
|---|---|
| 帧数不涨 | JS 没跑，或页面仍是旧版（缓存） |
| 帧数涨、相位不动 | 引擎没在推进 |
| 都正常却看不见动 | 才是渲染/视觉问题 |

这一行字把「到底哪一环断了」变成一个可以直接看到的事实。

## 一条新规律（写进 ROADMAP）

**「改了但没生效」要先排除「文件没到」**，再怀疑代码。
GitHub Pages 的静态资源默认缓存 10 分钟；发版后让玩家立刻看结果，
必须用版本串（`?v=`）把缓存打断——否则所有调试都建立在旧代码上。
