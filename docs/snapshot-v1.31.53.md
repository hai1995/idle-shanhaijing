## 本轮一句话

**舆图下线，撤干净。**

v1.31.51 做「道里图」、v1.31.52 改「舆图」——两版都是把 26 条经按方位摆到一张纸上。
用户看过后判断：**要的不是这种图**。要的是「2D 页游那种、角色能在地图上走的世界地图」。

## 为什么不做（判断依据）

技术上能做——已出原型（宣纸底 + 三层淡墨远山 + 三峰山形 + 朱印角色 + 虚线路径，纯代码绘制）。
但它需要三样这个项目没有的东西：

| 缺什么 | 说明 |
|---|---|
| **美术资源** | `assets/` 里只有一个 14KB 字体。所有图形都是手写 SVG path。原型能到「雅致」，到不了「页游」的精致度——后者靠反复对稿，不是一次写完 |
| **447 座山的二维坐标** | 原文只有「一维里程 + 方向」。世界地图必须自造布局，这是设计工作，也是最容易翻车的地方（前两版都栽在这） |
| **性质改变** | 点山名瞬移 → 走 3–10 秒；屏幕主体从文字变成图像。与「放置、能懒」有张力 |

所以**撤掉，而不是留一个半成品**。

## 有意保留了什么

原文里程的**读取判据**：

| 函数 | 管什么 |
|---|---|
| `regionLegs(region)` | 统一两种 `legs` 格式（对象式 `路线` 用 id / 数组式用 `from`·`to` 山名） |
| `regionRoad(regionId)` | 一条经的行程表：每座山的累计里程 |
| `regionRoadLength(regionId)` | 里程合计 |
| `roadBetween(fromId, toId)` | 两山路程；**跨经 / 跨系返回 null** |

它们不是「地图功能」，而是**对数据的解读**。将来若做「行进 / 路程」可直接引用，不必重写。

## 三条规律（写进 ROADMAP）

1. **用户说「想要地图」时，先问是哪一种**——一个词覆盖三件事：① 一张图（把山排在纸上）；
   ② 一个场景（角色在地形里走）；③ 一套空间关系（哪座山离哪座近）。成本差一个数量级，
   且顺序不能反：**先让用户看图，再谈做不做**。
2. **数据能导出形状，不等于能做出场景**——v1.31.52 证明了「方向 + 里程」能积分出真实走向
   （北经北上、南经东行），这是**取证**，不是**造景**。
3. **下线要撤干净**——入口、状态、脚本、样式、图标、判据全删，并写测试守卫。
